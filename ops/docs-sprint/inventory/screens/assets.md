Paths are relative to the repo root. `OP/` = `civiccast/apps/portal-operator/src/`. Backend = `civiccast/...`.

Cards named in the brief but rendered on **Channels**, not on Assets: `AudioTracksCard`, `LoudnessPlanCard`, `CaptionStatusCard` (section at the end).
Backend: `civiccast/schedule/router.py`, `civiccast/schedule/media_lifecycle_router.py`, `civiccast/schedule/store.py`, `civiccast/schedule/media_lifecycle_store.py`, `civiccast/schedule/media_lifecycle_worker.py`, `civiccast/captions/router.py`, `civiccast/summary/router.py`.

Who can open it: nav entry has no `requiredRoles` (`OP/components/shell/Sidebar.tsx:142`) so every signed-in operator sees it; routes `/assets`, `/assets/:assetId`, `/assets/:assetId/trim` (`OP/App.tsx:278-280`), alias `/archive` -> `/assets` (`OP/routes.ts:61`). No screen-level role gate; each control is gated only by the API (table below). While the first-setup recovery kit is unconfirmed every nav entry except Manual is disabled (`Sidebar.tsx:223,345`). A token with the generic `operator` or `admin` scope holds all five roles (`civiccast/auth/roles.py:23-24`), so role differences only appear for role-scoped tokens. Product roles: setup_admin, meeting_operator, records_clerk, publish_operator, support_admin (`roles.py:14-19`).

## What it is for
The library of every video the station holds: files uploaded here, files picked up from a watch folder, accepted contributor programs, and live recordings. The list shows each file's state and whether it can be streamed to residents. Opening a row shows an editor for the public title/description/meeting body/retention, technical details, readiness and legal hold, the offline caption job, and AI summary generation.

## What the user sees
**List page (`/assets`)**, top to bottom:
1. Small label "Library", heading "Assets" (`AssetsScreen.tsx:218-220`), and text "Recorded files uploaded for trim, scheduling, and publish. Files are kept untouched; trim and chapter edits are non-destructive." (`:222-223`).
2. Button "Upload video" (toggles to "Cancel upload") (`AssetUploadControl.tsx:197`); when open an "Upload video" panel (`:218`).
3. Search box, placeholder "Search by title or asset ID…" (`AssetsScreen.tsx:253`; aria-label "Search assets"), and tabs "All / Validated / Recorded / Analyzing / Rejected" (`:20-26`).
4. Table columns Title, State, Status, Duration, Size, Codec, Published, (Actions) (`:310-317`). Title shows the asset ID under it (mono). Title is a link-styled button (opens detail) with aria-label "Open detail for {title} ({id})" (`:340`).
5. Row actions: "Edit trim", "Package for playback" (see table).

**Detail page (`/assets/:id`)** (`AssetDetailScreen.tsx`): "← Back", "Library · asset detail", asset title and ID; left card "Public metadata" (Title, Description (optional), Meeting body (optional), retention controls, Save/Reset, then the custom-fields editor); right card "Technical" (State, Duration, Size, Codec, Resolution, Format, Published, Manifest, Trim window, Chapters, "Edit trim & chapters", then the "Media lifecycle" panel); below, "Offline caption jobs" card and "AI summary" card.

## States
- Loading list: three grey pulsing bars. Detail: "Loading asset…" (`AssetDetailScreen.tsx:142`).
- Empty list: "No assets yet." / "Use Upload video above, add a watch folder under Media Lifecycle Settings, or add a bundled sample from Setup." (`AssetsScreen.tsx:107-110`). Filter hides all: "No assets match the current search and filter." (`:295`).
- Error list: see Retry row. Detail error: "Could not load asset." + detail + "Back to assets" (`AssetDetailScreen.tsx:162,177`).
- **List size**: the page asks for `/api/staff/assets` with no paging; the server default is the first **50** rows, ordered published first then by asset ID, and returns the real total only in an `X-Total-Count` header that the console never reads (`schedule/router.py:245-280`, `schedule/store.py:191-216`; `OP/api/client.ts:609`; grep of `X-Total-Count` in `OP/` finds nothing). Search and the tabs filter only those 50.
- Readiness panel: pulsing bar; error `Could not load readiness: {detail}` (`MediaLifecyclePanel.tsx:100`).
- Caption jobs panel: "checking" chip; "No offline caption jobs for this recording yet." (`OfflineCaptionJobsPanel.tsx:121`).
- AI summary: "No committed transcript cues yet. Approve caption review items for this recording first, then a summary can be generated from them." (`GenerateSummaryPanel.tsx:103`).

## Typical task flows
1. Upload: Upload video -> pick file -> check the Title -> Upload -> wait for "Uploaded: {title}" -> row appears as Validated / "Not packaged yet".
2. Make it watchable: row -> Package for playback (publish operator/setup admin) -> Status "Packaged". Then publish on the Publish screen (that screen sets the publish date; approving publish also queues captions, see below).
3. Fix metadata: click title -> edit -> Save metadata.
4. Take a recording off the public portal: detail -> Technical -> Published -> Remove from portal -> confirm.
5. Legal hold: detail -> Media lifecycle -> reason -> Place legal hold -> confirm.
6. Captions for a recording: Publish screen approval queues the caption job (`civiccast/publish/router.py:306,473-481`; panel text "Approving this recording's portal surface on the Publish dashboard is what starts it"); when state is "Awaiting review", approve/edit/reject every cue in Review queue; captions attach only after **every** cue in the English pass (then the Spanish pass) is decided (`captions/vod_job.py:15-28`, `captions/vod.py:430-480`).

## Statuses and words on this screen
(`status-language.ts` is not used by this screen.)
**State column** (`OP/types/asset.ts:54-79`): Analyzing (`pending_ingest`; tooltip "ffprobe is running on the uploaded file."), Ingesting, Validated ("Ingest passed. Ready for trim, scheduling, or publish."), Rejected ("File failed the validation gate. See details for the next step."), Recorded ("Live recording is finalized and waiting for a publish workflow.").
**Status column** (`assetStatus.ts`, derived from the row; first match wins): Rejected (red, :60); Missing file (red, :71; tooltip "Backing file not found on disk; relink or replace the source."); Validating (`pending_ingest`, ":88 usually takes under a minute"); Ingesting; Published (publish date set, "Live on the resident portal."); Packaged (manifest set, "Playable and ready to publish or schedule."); Transcoding / Queued for transcode (amber, from the lifecycle worker; count in brackets); Not servable yet (`recorded`, no manifest: "Live recording is finalized but has no public playback manifest yet, so residents cannot stream it."); Not packaged yet ("Validated and ready for trim or scheduling. Use "Package for playback" to make it streamable.").
**Readiness badge in detail panel** (`ReadinessBadge.tsx:18-23`): Ready, Transcoding (n%), Queued for transcode, Missing, Rejected, Not ready. Loudness gate: "OK (-x.x LUFS)", "Failed — normalize before air", "Not checked yet" (target -16 LUFS +/-1 at ingest, `media_lifecycle_worker.py:144-145`). Archive rows: Portal (published) / Internet Archive / Local NAS each "✓ verified" or "not verified"; "✓ Archive-complete" / "Not archive-complete yet" (portal = packaged and published; IA/NAS need real, non-simulated proofs, `:700-710`).
**Caption job**: Transcribing… (n s/m) = `pending`; Awaiting review; Complete; Failed (`OfflineCaptionJobsPanel.tsx:26-36`; backend states `captions/vod_job.py:73`). **Summary job chip**: queued / generating… / done / failed.
Where each state really comes from: `validated` = every successful upload / watch-folder file / accepted contributor file / replace-source; `recorded` = live capture; `pending_ingest` = only the schedule-migration import (`civiccast/migrate/service.py:295`); `ingesting` and `rejected` are never set by any non-test code I searched (`schedule/`, `vod/`, `migrate/`, `contribute/`): UNVERIFIED (see below).

## Help-text findings
- [HELP-01] `AssetsScreen.tsx:222` header text never says the list is only the first 50 rows, that newly uploaded unpublished files sort after published ones, or that search covers only those rows — a station with >50 assets can upload a file and not find it. Fix: paginate (use `X-Total-Count`) or add "Showing 50 of N" plus a Next button.
- [HELP-02] `OP/types/asset.ts:55` / `assetStatus.ts:84` — State says "Analyzing" while Status for the same row says "Validating"; "Recorded" (amber) beside "Not servable yet". Two vocabularies for one thing. Fix: show one column, or rename State "Analyzing" to "Validating".
- [HELP-03] `types/asset.ts:58` tooltip "ffprobe is running on the uploaded file." — jargon, and `pending_ingest` is not produced by uploads. Fix: "CivicCast is checking the video file."
- [HELP-04] `AssetDetailScreen.tsx:823` Technical > State prints the raw code (`validated`, `pending_ingest`); the upload success text prints it too (`AssetUploadControl.tsx:322`). Fix: use the same labels as the table.
- [HELP-05] `AssetUploadControl.tsx:220` "The file is added to this list once ingest validation finishes." — validation is finished before "Uploaded" appears; a rejected file is not listed anywhere and leaves no row. Say: "If the file is not a supported video, you will see the reason here and nothing is saved." and state the size limit.
- [HELP-06] `AssetsScreen.tsx:222` and the Status "Package for playback" never explain Package vs Publish vs Remove from portal; the row can show "Packaged" and residents still cannot see it until Publish is approved. Fix: one sentence: "Package = make it streamable. Publish (Publish screen) = show it to residents."
- [HELP-07] `AssetsScreen.tsx:408,423` Edit trim / Package buttons appear only for `validated` rows although the API packages `recorded` rows too (`router.py:86,405`) and the detail page offers trim for `recorded`; `AssetDetailScreen.tsx:883-884` tells operators of a recorded file to "Set a public manifest URL in Setup", which contradicts the packaging path. Fix: show Package for `recorded`, drop the stale Setup sentence.
- [HELP-08] `AssetDetailScreen.tsx:771`, `:856`, `MediaLifecyclePanel.tsx:174-218,231` — Save metadata, Remove from portal, Legal hold and Replace source are all clickable for every role; a wrong role gets the raw API text "This action requires one of these CivicCast roles: …" after clicking. Fix: disable with the role named, as Package already does.
- [HELP-09] `MediaLifecyclePanel.tsx:159` "Archival (CLAUDE.md §4.6): portal + Internet Archive + local NAS, all verified" — a developer file reference in the UI. `:144` "Failed — normalize before air" has no control or help for normalizing. Fix: "All three copies (portal, Internet Archive, local NAS) have been checked." and say where to fix loudness (or that it is informational).
- [HELP-10] `MediaLifecyclePanel.tsx:254` replace-source dialog says every viewer sees the new file "immediately once processing finishes". The code resets the row to `validated` but leaves the old package/publish date untouched (`media_lifecycle_store.py:427`, no repackage call anywhere after replace), so residents keep the OLD video until someone packages again. Fix: "After replacing, use Package for playback again."
- [HELP-11] `OfflineCaptionJobsPanel.tsx:46` "Measured ~37 seconds for 11 seconds of audio on a 32 GB CPU-only reference machine" — lab figure; a volunteer cannot map it to their PC. Fix: "Transcribing a full meeting can take longer than the meeting itself."
- [HELP-12] `OfflineCaptionJobsPanel.tsx:49` "waiting in the caption review queue" — does not say that nothing is attached to the video until **every** cue is approved, edited or rejected, nor that "Review queue" is in the left menu. Add both.
- [HELP-13] `assetStatus.ts:71-77` (status "Missing file", also the same words in `media_lifecycle_worker.py:633`) tell the operator to "relink or replace the source", but the console has no relink control (grep of `OP/` finds no `relink` API function); only Replace source file (publish_operator/setup_admin) exists.
