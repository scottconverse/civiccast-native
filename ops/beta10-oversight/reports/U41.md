## 2. Work 1 — why only 80 s of lead, and what I changed

### 2.1 The mechanism (file:line)

The lead is **not** a cadence. It is the runway the rollover is issued with so that a preparation
running to its *configured bound* can still settle before the outgoing plan reaches EOS.

* `civiccast/egress/automation.py:1472 _rollover_lead_seconds()` computes it:
  `max(_ROLLOVER_MIN_LEAD_SECONDS, 2 × preparation_timeout + settle_budget + margin)`
  = `max(120.0, 2×300 + 30 + 60)` = **690 s** at the shipped 300 s preparation timeout.
  Constants: `_ROLLOVER_MIN_LEAD_SECONDS = 120.0` (:953),
  `_ROLLOVER_RELOAD_SETTLE_BUDGET_SECONDS = 30.0` (:973), `_ROLLOVER_LEAD_MARGIN_SECONDS = 60.0`
  (:974), `_ROLLOVER_PREPARATION_PASSES = 2.0` (:995).
* The trigger is clamped so a plan shorter than the lead is not triggered before it starts airing:
  `trigger_at = max(last_segment_start_at, plan_end_at - lead)` (automation.py:1991-1994 in the
  U41 tree; `:2005-2007` at `e1189cae`), then `if now < trigger_at: return` (:2007 at base).
* The **D43 cadence floor** (`_rollover_min_interval_seconds` = `min(300, max(1, 0.5×planned))`,
  :1056/:1070/:1605) is a *separate* gate that can hold a dispatch back — it is sized to the plan
  now on air but measured from the previous dispatch (automation.py:2009-2020 at base).
* While any reload is settling, no new rollover is even considered:
  `automation.py:1914-1921` — `if channel_id in self._rollover_issued: if
  self._daemon_has_pending_reload_settlement(channel_id): return`, silently, with no log line.
* A past-due "still settling; waiting" line exists (`automation.py:1879`) but only fires when
  `plan_end_at <= now`; it never appeared in the incident window (OBSERVED: no such line in
  `evidence\education-exit0-2354\`'s window — `grep` over `%TEMP%\u41\incident.txt` returns none).

### 3.2 After (OBSERVED at HEAD)

At the plan's EOS, on the **current program leg's** selector sink pads (video + audio, one probe
each), the EOS is declined before it can cross:

* `engine.py:5129 _is_current_program_pad` — identity, never name or value; a displaced pad (a
  superseded transaction's) is not the pad on air.
* `engine.py:5143 _arm_plan_eos_hold_probes` — installs the probe on `selector_sink_pads[0]` and
  `audio_sink_pads[0]`; best-effort, and a pad that refuses the probe keeps the *pre-U41* behaviour
  rather than becoming a new failure.
* `engine.py:5175 _on_program_pad_plan_eos` — returns `DROP` when the hold is armed,
  `_pending_reload is None`, there are ≥2 legs, the pad is the one on air, and the event is really an
  EOS. Prints
  `CTRL plan EOS: program leg ended with no reload in flight; holding the slate`.
* `engine.py:5231 _hold_slate_for_plan_eos` — main-loop callback; re-checks the same guards, then
  `self.swap.swap_to(_SLATE_LEG_INDEX)` (`_SLATE_LEG_INDEX = 1`, engine.py:612 — the second leg
  `bridge.py` builds, the always-hot live/infinite slate), sets `_plan_eos_held = True`, prints
  `CTRL plan EOS: slate on air; the channel stays up until the replacement is ready`. If the swap
  itself fails, the output really would freeze with no signal, so it fails the worker explicitly
  (`self._error` + `self._loop.quit()`) and lets the daemon restart — the same escalation the S9-5
  stall watchdog uses.
* `engine.py:3828` — `"old_leg_eos": (not switch_at_end_of_current) or self._plan_eos_held`. Without
  this, a reload dispatched after a held plan end would arm the 900 s `defer_switch_timeout_s` for a
  boundary that has already passed, with the slate on air the whole time. With it, the deferred
  reload commits the instant the replacement's first buffer lands.
* `engine.py:4767-4768` — `_confirm_reload_selector_handoff` clears `_plan_eos_held` and re-arms the
  probes, because the commit replaced `selector_sink_pads[0]`/`audio_sink_pads[0]` with new objects;
  a probe left on the displaced pad would guard a leg the channel no longer airs.

The hold is armed **only in `run_forever`** (`engine.py:3444`). `engine.run(swaps, interval_s)` — the
finite smoke mode — never arms it and keeps exit-at-plan-EOS. `worker.py:557` reads `SWAPS`; a
non-zero value runs `run()`; nothing in `daemon.py` sets `SWAPS`, so production and the beta.5 pin
both run `run_forever` (INFERRED from `worker.py:557-566` and a `grep` for `SWAPS` across the daemon).

### 3.3 The premise gap (this is what I stopped on)

The brief's Work 2 says *"while a reload is being prepared"*. That is not a state the worker can
observe:

* The worker's control vocabulary is closed — `civiccast/egress/gst/worker.py` and `engine.py`
  handle exactly `swap`, `reload`, `caption`, `stop`. There is no "I am preparing" verb.
* `strategy.py:_default_worker_launcher` (~678-681) only *strips* `SWAPS`/`INTERVAL` from the
  environment; argv is `[python, worker.py, <graph.json>, <control channel>]` (`strategy.py:980`);
  `EncoderStartRequest` (`civiccast/egress/encoder_strategy.py:25-77`) has no live flag.
* The field timeline proves it: the replacement was *queued* at 23:53:33 and the worker reached EOS
  at 23:54:41 with `pending_reload=False` — no `reload` command existed anywhere in that window.

So the only honest predicate at the EOS is `self._pending_reload is None`, which is exactly what the
committed hold tests. It fires in the field's shape (correct — otherwise ~3 min dark) **and** in the
beta.5 pin's shape, where the pin says the opposite. Full analysis, evidence and options A / A′ / Y
with my recommendation (A) are in `questions\U41.md` §2-§5. No code change until that is answered.

### 14.1 Where the plan horizon is computed (file:line)

### 14.2 The rule, stated

When a rollover is **deferred** (`should_defer_switch(..., now=None)` true, i.e.
`switch_at_end_of_current`), the new plan must extend to at least `expected switch time + lead`.
**Items are not split and nothing is re-planned otherwise.** Two deliberate exclusions, both
**OBSERVED** in the code and its comments: a `force_fallback` filler rollover is excluded (that branch
is the slate fill by design), and the eligibility decision is taken in its `now=None` form on purpose
— the *late* `now` handed to the encoder below is item 78 fix 3's stale-horizon cut and must stay
late. **INFERRED**: the two can disagree only if the boundary passes between this point and the
request build, and the cost of that rare disagreement is a wider plan, nothing else.
