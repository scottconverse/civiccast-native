# U72 — the caption decode can no longer be broken by a bad diagnostic, and a batch that failed before its decode can no longer be blamed for someone else's seconds

**Slice:** `beta10-u72`. **Base:** `faaf62ea` (`beta10-u71`'s tip). **HEAD:** `a37f1a40`.
**Commit:** `a37f1a40` (single commit, `fix(captions)`).
**Station action: none. Nothing installed, nothing pushed.**

Closes **M-1** and **M-2** of `reports/U71-AUDIT.md`, and replaces the one new U71 test
that asserted only its own literals (**M-5**), plus the two doc corrections the brief
named. **M-3** and **M-4** were deliberately left — see §5.

## 1. In plain English

Two small hardening gaps that the U71 audit rated *Minor* both sat on the live caption
tap's decode path. Neither could hurt a transcript today only because the inputs that
trigger them do not occur in practice — which is exactly the kind of "not reachable yet"
that turns into an outage when faster-whisper changes or a new chunk shape arrives.

**M-1 — a diagnostic must not be able to kill the decode.** The runtime reads
`duration_after_vad` off the model's *own* `info` object and coerces it to a float for the
shed diagnostic. Two shapes took the whole decode down with them: an `info` whose
`duration_after_vad` is a *property that raises*, and an int too large for `float`
(`float(10**400)` raises `OverflowError`). In both cases a number the diagnostic merely
*wanted* destroyed a transcript the station *needed*. The read is now guarded — any
exception degrades to `None` — and the shared `_optional_float` helper catches
`OverflowError` alongside `TypeError`/`ValueError`. A diagnostic that cannot be taken is
JSON `null`, never an error.

**M-2 — a batch that never decoded must not be stamped with another batch's numbers.**
`last_decode_metrics()` is a per-thread record: one runtime serves every channel, and each
channel decodes on its own pooled executor thread. The tap reads that record on the same
thread immediately after `process_batch` returns. If a batch failed *before* its decode —
the audit's concrete case is the temp-WAV write for a non-16 kHz chunk — the slot still
held the **previous** batch's numbers, so a batch that never decoded was reported with
someone else's `transcribe_s` and `duration_after_vad`. `FasterWhisperRuntime.transcribe`
now clears the slot as the batch begins, so the failed batch reads `None`. The reset sits
at the top of the generator body, which runs on the first `next()` — before any per-chunk
work that can fail — and the per-thread design is unchanged.

**M-5 — a test that could not fail.** The U71 preparer test
`test_the_registry_spelling_is_the_two_c_one` compared test-local literals to each other
(`assert self._PRIMARY == "CIVICCAST_…"`), so it passed on *any* code, including code with
the very defect U71 fixed. It now binds to the module's own constants
(`preparer_module.FOREGROUND_PREPARATION_LOW_PRIORITY_ENV` and
`…LEGACY_FOREGROUND_PREPARATION_LOW_PRIORITY_ENV`) and is a real source-binding guard: it
passes at u71 and **fails at u70** — where the legacy constant does not exist at all and
the primary one still held the one-C value. This test is a **guard, not a RED-on-u71
test** (u71's source is correct; there is nothing for it to fail against).

**Docs.** `docs/ops/background-workers.md` overstated one thing: "all four are `null` when
the runtime does not publish them" implies a single cause for a `null`, but a `null` has
three. `persist_s` is a residual and is also `null` whenever `asr_s` or `stabilize_s` is
unknown, and `max_segment_temperature` is `null` when a chunk yielded no segments — a
different fact from "the runtime publishes nothing". The sentence is corrected, and a new
line records that the two-C `CIVICCAST_…` spelling is primary with the one-C spellings
kept as deprecated legacy fallbacks.

## 4. What I could NOT measure

- **Nothing was run against the live station and nothing was installed.** The whole slice
  is proven with fakes and a synthetic `info` object; the runtime's model is never loaded.
  Both fixes are on the decode path the fakes stand in for, so the *logic* is proven, but
  no real whisper model, no real channel, and no real pooled thread was exercised.
- **The live incidence of M-2 is unmeasured.** The audit's reproduction was synthetic; how
  often a real batch reaches the pre-decode failure points (the temp-WAV write for a
  non-16 kHz chunk, or a `ValueError` from `np.frombuffer` on an odd-length PCM buffer) is
  not observable from this seat. The fix is correct whether or not it fires; it is not
  claimed to fire.
- **M-1's raising-`info` shape is synthetic.** A faster-whisper `TranscriptionInfo` whose
  `duration_after_vad` is a raising property does not exist in the pinned version. The fix
  is defensive against a future or substituted runtime object, not against an observed one.
- **The rewritten M-5 test is a guard, not a RED-on-u71 test.** It is proven to fail on
  u70 source; it cannot fail on u71 source, because u71 source is correct. That is the
  intended shape, but it means this unit's RED/GREEN evidence for M-5 lives one revision
  behind its base.

## 5. Risks / judgement calls

| item | assessment |
|---|---|
| **M-3 left, deliberately** | Minor, cosmetic: in the *non-live* batch path `yield hypothesis` sits inside the timing `try`, so `transcribe_s` there includes consumer time. The audit calls it a one-line-comment fix and notes the tap only reads it for the live runtime, so there is no output change today. The brief scoped U72 to M-1/M-2/M-5 + docs; adding a comment to a path U72 otherwise does not touch would widen the diff for zero behavioural value, so it is recorded open rather than folded in. |
| **M-4 left, deliberately** | Minor, diagnostic-only: `_optional_rounded` (`civiccast/captions/tap_shed_diagnostic.py:190`) does not reject NaN/inf/negative, so a direct caller could emit non-RFC JSON (`Infinity`/`NaN`) and a derived `persist_s` from a negative `transcribe_s` would be nonsense. It is not reachable from the runtime (`_optional_float` filters with `isfinite`; `perf_counter` deltas are finite and ≥ 0). Fixing it would add a **second installed file** to a carry deliberately kept to one, for a gap the audit itself rates unreachable — so it stays open. |
| **Resetting the slot cannot hide a real decode** | The reset runs at the top of the generator body, before the per-chunk work. A batch that *does* decode re-writes the slot in `_transcribe_chunk`'s `finally`, so the reset can only ever be observed by a batch that failed before decoding — which is the batch that should read `None`. |
| **The reset costs the hot path nothing** | One attribute assignment per batch, on the runtime's own `threading.local`. `transcribe()` is called once per batch, not per chunk. |
| **`_optional_float` now swallows `OverflowError`** | Intended: an unrepresentable number is a diagnostic that cannot be taken, not a decode error. `OverflowError` is not a subclass of `TypeError`/`ValueError`, so it had to be named explicitly. |
| **`duration_after_vad` guarded broadly (`except Exception`)** | Deliberate. The object is the model's, not ours; the only requirement is that reading a *diagnostic* never fails the decode. A narrower `except` risks missing a future property's exception type. The guard cannot mask a decode failure, because it wraps only the attribute read. |
| **The M-5 test now imports `preparer_module`** | `preparer_module` is already imported at module scope in `test_preparer.py` (used throughout); the rewrite adds no import. |
