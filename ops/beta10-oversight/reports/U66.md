## 1. The answer in plain English

C15 (2026-09-29 07:18) filed loudness check #9 as a **FAIL** on `education`: the 07:14–07:18
window measured **−21.9 LUFS** against a −16 ± 1 target. The tool then had to answer "where in
the source does this window sit?", and it answered **3226.3 s** — from the log. The window was
really at **7121–7206 s** of the 15,949 s August 11 meeting (U64's re-measure and the
coordinator's). The ruling was a loudness verdict about audio the tool had placed **~3900 s
wrong**, and it survived because nothing in the run could contradict it.

Three things were wrong, and they compound:

1. **The rung never gave the adjudicator any audio.** `rung_check.adjudicate()` invoked the
   adjudicator with the evidence path and `--quiet` and nothing else, so `--air-audio` was never
   passed and the correlation (T1) — the one signal that could have contradicted the log — never
   ran. It was structurally impossible for it to run.
2. **Even handed air audio, the correlation had only one try.** It looked in a ±900 s
   neighbourhood of the log's own position. Around a position that is 3900 s out, there is
   nothing to find, so a wrong log would have beaten a correct measurement.
3. **The log's position was not merely imprecise — it was an inference from a truncated run.**
   The station played this meeting in ~1800 s parts, each a fresh ON_AIR of the *same* display
   name, back to back. The adjudicator collapses a run of identical sources into one transition,
   so the run it sees starts at **part one**, and the window's "time into the run" counts every
   part before it. That is the 3226.3 s: a real number computed from the wrong start. There is no
   tolerance rule that fixes that; the position is simply not a measurement.

What the candidate does:

- **Item 1** — the rung concatenates the capture's own snapshot segments (the audio the capture
  measured, named by `loudness.json → channels[].segments[].snapshot_path`) into one file per
  channel and passes it as `--air-audio CH=path`. Best-effort by design: the capture tree prunes,
  so a missing chunk is skipped and, if nothing survives, no air audio is passed at all (fail
  closed — see the disclosure in §5.4).
- **Item 2** — T1 now runs in four attempts, cheapest and most anchored first: the log's ±900 s
  neighbourhood (whole slice), that neighbourhood on its loud part, **the whole asset** (whole
  slice), the whole asset on its loud part. The whole-asset attempts decode once, at **IDLE**
  priority, and are cached; because they exist *because* the log can be wrong, they are allowed
  to disagree with it and the disagreement is reported as a finding rather than used to discard
  them. The loud-part path is the U64 lesson made executable: a quiet head correlates badly, so
  the loudest contiguous half of the window is split in two, each half correlated independently,
  and the answer is accepted only when both lock *and* their lags agree (a real lock repeats
  under the split; a coincidence does not).
- **Item 3** — if T1 still fails to place the window, the tool checks whether the log's position
  is even usable: the window more than **1800 s** into one run, or the same display name on air
  more than once for that channel before the window. If either holds, the tool **stops before
  measuring** and returns `BORDERLINE` / `position unresolved: multi-part asset, log position
  unreliable`, instead of a loudness verdict computed at a position it does not believe.

The replay of the real C15 evidence, with the real log and the aired-audio fixture, now answers:

```

pos=7206s(correlation) src45min=-47.247LUFS srcspan=-44.674LUFS maxreach=-29.247LUFS
air=-21.9LUFS unreach=197/197s (range 197-197, need 61) window=241.667s
```

against the baseline's, from the identical command:

```

src45min=-29.277LUFS srcspan=-23.288LUFS maxreach=-11.277LUFS air=-21.9LUFS
unreach=0/197s (range 0-0, need 61) window=241.667s
```

The position moves **3979.7 s** and the ruling inverts — not because any rule was relaxed, but
because the window is now placed by measured audio: at 7206 s the source's own ride window cannot
reach the target's lower edge even at the +18 dB ceiling (`lift_limited_lufs + g_max_db =
−47.247 + 18.0 = −29.247`, the printed `maxreach` — still **12.2 dB short** of the −17.00 LUFS
acceptance floor the criterion uses, `target − tolerance`), so 197 of 197 scorable seconds sit

owner's quiet source, not a station fault.

## 2. What changed, by work item

### Item 1 — the rung hands the adjudicator the audio the capture heard (`staging\U66\rung_check.py`)

- `channel_air_audio(channel, chan, scratch_dir=None)` (new, `rung_check.py:162`): collects the
  channel's `segments`, sorts by `sequence`, skips any `snapshot_path` that is missing/empty,
  and copies the survivors **byte for byte** into `<scratch>\<channel>-<key>.aac.ts` via a
  `.part` file and `os.replace` (atomic — the adjudicator may be reading the scratch tree
  while a later run rewrites it). No decode, no re-encode: consecutive MPEG-TS chunks joined
  end to end are one stream to a decoder, and re-encoding would put this script in the signal
  path. The concat is keyed on the **ordered segment digests**, so the same window re-captured
  into a fresh scratch directory reuses the same file; the previous window's sibling concat is
  deleted so a stale file cannot be read as this window's evidence. Returns `None` when there is
  nothing to concatenate or on any `OSError`.
- `adjudicate(path, air_audio=None)` (`rung_check.py:117`): each entry becomes
  `--air-audio CH=PATH`, sorted for a stable argv.
- Dispatch (`rung_check.py:710-728`): the concat is built **only** for channels that are non-PASS
  *and* not instrument errors — the same predicate that already gates whether the adjudicator
  runs at all, so a PASS channel or a channel with no measurement costs nothing.
- Scratch root: `CIVICAST_AIR_AUDIO_DIR`, else `%TEMP%\cc-loud-adj-scratch\air`.

### Item 2 — the adjudicator's T1 (`staging\U66\loudness_window_adjudicate.py`)

- `air_lock(args, asset_path, air_file, t2)` (`:1073`) — the four attempts described above.
  Attempts 1–2 keep the pre-existing ±60 s T1/T2 agreement rule; attempts 3–4 are
  `log_independent` and **report** `agrees_with_log_within_s` without being disqualified by it.
  The whole-asset profiles are fetched through `cached_series(..., priority=IDLE_PRIORITY_CLASS)`
  (`:1182`); the near-window profile stays `below_normal`. One ffmpeg at a time, cache-keyed on
  content identity so the IDLE pass is reused by every later call.
- `loud_part_correlate(air_blocks, ref_blocks, ref_start_s)` (`:952`) — the loud-part path:
  `_loud_region()` picks the loudest contiguous half of the window (never shorter than
  `LOUD_PART_MIN_S`), splits it in the middle, correlates each half independently under the same
  `r >= AIR_MIN_R` / `margin >= AIR_MIN_MARGIN` test, subtracts each half's offset inside the
  region so both halves answer the same question, and accepts only when they agree within
  `LOUD_PART_AGREE_S` — the disjoint-slice acceptance the brief asks for. The reported
  `position_s` is `ref_start_s + lag − start_in_window`, i.e. the **window's** start, directly
  comparable with `correlate()` and with `t2`; each half's own lag is reported as `region_lag_s`.

### Item 3 — the multi-part guard (`staging\U66\loudness_window_adjudicate.py`)

- `multi_part_airing(...)` (`:330`): true when the same display name went on air **more than
  once** for this channel before the window, or when the window sits **more than
  `MULTI_PART_T2_S = 1800` s** into one run. Deliberately conservative and documented as such:
  a long *single-leg* unattended airing is possible, which is why it only ever produces a note.
- `:1352-1365`: consulted **only when `source == "log"`** — a supplied position is the caller's
  assertion and a correlation lock is measured audio, but the log is an inference. On a hit the
  tool returns `classification = BORDERLINE`, the detail string, and **returns before the source
  measurement**, so no loudness verdict is computed at a position the tool does not believe.
- `rung_check.label()` (`:332`): a non-PASS channel whose adjudicator classification differs from
  its status prints `FAIL/BORDERLINE(...)`, and the unreach token travels with it
  (`unreach_token(got) if got.get("borderline")`) so the human reading the line sees the sweep
  range that straddles the need.

### Item 4 — the tests

- `staging\U66\test_rung_check_air_audio.py` (new, 6 tests): drives the **real** `rung_check.py`
  as a subprocess with a stub adjudicator beside it, so what is asserted is the argv the rung
  actually built and the line it actually printed: the concat is the capture's own bytes in
  sequence order; a swept snapshot is left out; **no** surviving snapshot means **no**
  `--air-audio`; an instrument-error channel is never adjudicated and never concatenated
  (asserted as the stub never being run at all); a PASS channel is never concatenated; the same
  window reuses its concat (mtime unchanged) and a different window replaces it and leaves no
  stale sibling.
- `staging\U66\test_loudness_window_adjudicate.py` (22 tests — the baseline's 10 kept intact,
  12 added; `+373/−0`): the whole-asset retry,
  the four-attempt order and the log-independent reporting, the loud-part acceptance/refusal
  matrix (halves agree / disagree / one half will not lock / a short window's loud region is the
  whole window / a quiet-headed window still places), the multi-part triggers (more than one
  ON_AIR run of the name; a leg past the 1800 s threshold; quiet on an ordinary single leg;
  another channel's runs do not count), `test_multi_part_window_with_no_correlation_is_borderline`,
  `test_air_lock_without_air_audio_says_so_and_touches_no_ffmpeg`, and the brief's positive
  control `test_single_part_window_still_uses_the_log_position_unchanged` (a 400 s single-part

## 5. Risks, disclosures and open questions

### 5.1 The whole-asset passes did not literally use `bin\monitors\lowloud.ps1`

The brief requires heavy read-only measurement to run at idle priority *via* that wrapper, one at
a time, ≤ 10 min. The two passes were IDLE-priority invocations of the adjudicator's **own**
measurement path (`ebur128_series(..., priority=IDLE_PRIORITY_CLASS)`) — same ffmpeg, same
arguments, same priority class the wrapper sets, sequential, 371.76 s and 428.39 s. They met the
intent and not the letter. The cache entry is disposable: deleting
`%TEMP%\cc-loud-adj\000310d4bcc4e87bc2b2795a.json` makes the tool re-measure it (in one ~800 s
pass) the next time a window needs it.

### 5.2 The cached whole-asset series is a two-pass stitch, not a single decode

0.499 s of 15,949 s (0.003 %) is a hole rather than a measurement. It cannot move a correlation
on a 1 s grid, and the acceptance test in §3.1 passes with `r = 0.954`. Two payload fields —
`ebur128_integrated_lufs` and `ebur128_true_peak_dbfs` — are carried from the two passes rather
than produced by one; **no code reads either** (verified: both are only ever written, at
`:587-588`; the reader is `blocks`). If the coordinator prefers an authoritative entry, delete
the file (§5.1) — the cost is one 800 s IDLE pass.

### 5.3 Item 3's `BORDERLINE` still leaves the soak `BAD` — deliberate

The brief says: never FAIL or EXCLUDE on T2 alone in the multi-part case. The tool obeys — it
returns `BORDERLINE` and measures nothing. But the rung's verdict is `BAD` whenever a non-PASS
channel has no applied exclusion, and I **did not** change that: a window nobody can place is
not evidence that the station is healthy, and a rung that passes because its instrument is
confused is exactly the failure mode U48 built `INSTRUMENT_ERROR` to stop. What the coordinator
gets is a line that says `FAIL/BORDERLINE(position unresolved: multi-part asset, log position
unreliable; unreach=…)` — a human-read flag, not a confident FAIL. If the intended reading is
"BORDERLINE should let the soak pass with a note", that is a small change to the `ok` computation
in `rung_check.py` and it is **not** in this candidate.
