## 3. Per-hunk description

### U11 — caption tap (`captions/tap_worker.py`)

**f7ad15b3** (23 hunks, +250/−26) and **5a046836** (1 hunk, +4/−4):

- Adds `_discard_pre_existing_segments`, called from `CaptionTapWorker.__init__`, so the
  worker discards leftover segments from a *previous* process's session at construction
  time, not only at session start.
- Adds a `context` parameter to `_discard_settled_segments` (`"worker startup"` at the
  construction path) so the diagnostic names *why* the discard happened.
- Adds the overload-persistence window: `DEFAULT_OVERLOAD_PERSISTENCE_SCANS` (installed 0 →
  candidate 3) and `overload_persistence_scans` setting (installed 0 → candidate 10), plus a
  backlog streak. A single over-limit scan is now **deferred, non-punitive**; only a
  persistent backlog is acted on.

*(This is the direct answer to the coordinator's question — see §5.)*

### U12 — relay video+audio lock (`egress/hls_relay.py`, `egress/sinks.py`, `egress/daemon.py`)

**1af28f88** (hls_relay 12 hunks +304/−13; sinks 1 hunk +14/−0; daemon 3 hunks +69/−9),
**8e9c3845** (daemon 1 hunk +3/−3), **9f1fdc6e** (hls_relay 13 hunks +196/−124; sinks 1 hunk
+31/−11; daemon 6 hunks +20/−16):

- `EgressSink.carries_video` — a sink now declares whether it carries video, so an
  audio-only sink is not treated as a full relay.
- `_relay_map_args(carries_video=, carries_audio=)` — the relay map is built from the kinds
  the source actually carries instead of a fixed video+audio assumption. This is the symbol
  whose absence makes the pristine `test_hls_relay_video_lock.py` a collection error (§6).
- `_segment_stream_kinds()` — tri-state (video / audio / video+audio / unknown) per segment,
  determined by probing with ffprobe. `_FFPROBE_EXECUTABLE = "ffprobe"`,
  `_SEGMENT_PROBE_TIMEOUT_S = 10.0`.
- `HlsRelaySupervisor.maybe_restore_missing_streams` + daemon `_restore_relay_streams` — a
  relay that came back audio-only is detected and restarted, with a bounded, backed-off
  restart cadence so a permanently-failing probe cannot spin.
- **Fail-safe:** `None` from the probe never triggers a restart. A probe that cannot run
  degrades to silent self-heal, never to a spurious restart.

## 8. Doubts

1. **The ffprobe PATH resolution is INFERRED, not directly observed for the relay child.**
   I observed the directory is on the control-plane child's PATH and that other media
   subprocesses resolve there, but I did not observe a relay-side `ffprobe` invocation in the
   log (the feature is not installed, so there is nothing to observe). If it did not resolve,
   the consequence is the safe one — no restart, no crash — so this is a low-risk gap, not a
   blocker.
2. **An already-running gst worker keeps the old engine.** The install is not complete for
   U14's engine half until the channel's worker respawns. The coordinator should plan the
   respawn rather than expecting the engine diagnostics immediately.
3. **`tap_worker.py`'s CRLF encoding is load-bearing for the step patches.** The candidate is
   CRLF (as installed); the patches are LF. Anyone re-running the reconstruction must
   LF-normalize the base first and re-encode, or the patches fail with "different line
   endings". Recorded so the next unit does not rediscover it.
4. **The two excluded 52-/62-line features (`_STALL_DIAG_ENV_VAR`, batch diagnostics) exist in
   the worktree HEAD blob but not in the candidate.** They are uncommitted beta.10 work from
   `03a90b9d`. If U16/U17 install a state that assumes one of them, the candidate could
   conflict. Flagged, not resolved — it was outside this unit's brief.
