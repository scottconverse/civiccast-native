# U65 — the conform cache invalidates itself: a probe-only metadata write erases a promoted full-asset conform's markers

**Slice branch** `beta10-u65`, base `ce71c40a6c7b85e571a80f1317713d943fb4c006` = the station's
**LIVE bytes** (`preparer.py` blob `724fbfa2`, `loudness_ride.py` blob `3aff1900`, both verified
against `C:\Program Files\CivicCast (Native)\runtime\Lib\site-packages\civiccast\egress\`).
**No station action was taken.** Nothing was installed, restarted, signalled, or written under
`C:\ProgramData` or `C:\Program Files`; nothing under `…\data\egress\live-hls\` was opened or
held; no conform-cache `.ts` was opened (sidecar `.json` files only, read with shared reads).

---

## 1. The answer in plain English

The conform cache is two files per key: the encoded artifact `{key}.ts`, and a small JSON
sidecar. A cache **hit** needs both — the `.ts` **and** `full_asset_conform: true` in the
sidecar. The sidecar is not six independent fields: `_write_cache_meta` writes the whole file at
once by `tmp.replace(final)`, replacing whatever was there.

That function has exactly two callers, and they have opposite authority:

* the **promotion** write inside `_promote_conform_into_cache` — the one authoritative place a
  finished 4.4 h conform is marked reusable; and
* a **probe-only** write that records "I measured this key's loudness", made for a key whose
  conform was never promoted.

Both write to the same `{key}.json`. The probe-only write carries no promotion and no `.ts`, but
it *replaces* the file — so if it lands after a promotion's write, it wipes
`full_asset_conform` and `loudness_method` off a ~11 GB artifact that is sitting right there on
disk. The `.ts` survives; the marker does not; the next prepare sees a MISS and re-encodes the
whole asset. That is the reported symptom, exactly.

Within a *single* prepare this cannot happen: the probe branch is only reached when the read at
the top of `_prepare_segment` found no meta, and a prepare that goes on to promote writes its
promotion meta after its probe. The loss therefore needs **two prepares for the same key at
once** — which is ordinary on this station: three channels on ~30-minute reloads, and on
2026-09-29 between 06:22 and 11:04, **17 of 30 preparations were real conforms** (220–450 s each)
against 13 hits, several of them in the same minute as another channel's.

The fix: `_write_cache_meta` gains `only_if_absent`, and the probe-only call site passes it. With
the flag set the sidecar is published with `os.link(tmp, final)` — **create-if-absent** — instead
of `replace`. A `FileExistsError` means somebody else's marker is already on disk, so the probe's
write is dropped and theirs survives. The filesystem arbitrates the race; there is no lock, no
read-modify-write, no TOCTOU window. The hard-link-to-publish shape and its fallback are already
this module's idiom: `_promote_finished_conform_into_cache` uses `os.link(finished_output_path,
tmp)` on the `.ts` side (`:1386`) under the same `except OSError` cross-volume branch, so the
kernel — not application code — decides what exists there too.

And it changes no audio byte. In the uncontended case — every prepare except the race — there is
no sidecar on disk when the probe branch runs, so the link always succeeds and behaviour is
byte-for-byte what it is today. The fix is a no-op everywhere except in the race it fixes.

### The order within one prepare — and why the fix is about *across* prepares

`meta` is read **once** per prepare, near the top of `_prepare_segment`. The probe-only branch is
only reachable when that read returned `None`, i.e. when the sidecar did not exist. So within one
prepare, probe-write → promotion-write is the only order, and the probe cannot clobber its own
promotion. The race is across two prepares for the same key — the ordinary multi-channel case this
station runs constantly (evidence above).

### `_promote_conform_into_cache` is the sole promotion choke point, and three producers feed it

`preparer.py:1251` — `cache_dir.mkdir(parents=True, exist_ok=True)`; `tmp.replace(final)` (:1298,

## 3. Item 2 — the fix, and why this one

**`_write_cache_meta` gains `only_if_absent: bool = False`; the probe-only call site passes
`only_if_absent=True`.** With the flag the temporary JSON is published by `os.link(tmp, final)`:

```python
final = cache_dir / f"{key}.json"
tmp = final.with_name(final.name + ".tmp")
tmp.write_text(json.dumps(meta), encoding="utf-8")
if not only_if_absent:
    tmp.replace(final)
    return
# U65: atomic create-if-absent. ``os.link`` raises ``FileExistsError``
# when ``final`` already exists, rather than overwriting it the way
# ``replace`` does, so the FILESYSTEM arbitrates the race. ...
try:
    os.link(tmp, final)
except FileExistsError:
    # ... Theirs wins; this probe's result is dropped. ...
    if self._read_cache_meta(key) is None:
        tmp.replace(final)
except OSError:
    tmp.replace(final)
finally:
    tmp.unlink(missing_ok=True)
```

**The brief offered two options — merge rather than replace, or skip the probe write when a
promoted conform exists — and said to pick one and say why. This is the second, generalized and
made atomic.**

* *Why not merge.* Reading the existing sidecar, splicing in the probe's fields, and writing it
  back is a read-modify-write with a window between the read and the replace. Closing that window
  needs the per-key conform lock — which the air path deliberately takes **non-blocking** and
  which is held for the **whole ride**, minutes at a time. A probe write that blocks on the
  conform lock would stall a prepare behind an encode; a probe write that proceeds without it has
  the same race back, just narrower and now silent. Merging is also semantically wrong: it would
  let a stale probe's measurement overwrite a fresher one, and it invents a precedence rule
  between two writers that do not actually disagree about anything the reader uses.
* *Why generalize "when a promoted conform exists" to "when any entry exists".* The narrower
  rule needs a read-then-test — the same non-atomic shape — and it lets a probe overwrite a probe,
  which is a silent data-quality bug for no benefit. Create-if-absent needs **no read at all**:
  `os.link` cannot succeed over an existing file, full stop. Whether the incumbent is a promotion
  or another probe, the first writer wins and the second is dropped.
* *Why atomic here matters.* A cache HIT is the only thing standing between the station and a
  220–450 s re-encode. A fix that narrows a race without closing it is not a fix; `os.link` closes
  it with a single atomic syscall.
* *Why the fallbacks are safe.* `except OSError` covers filesystems without hard links (FAT, some
  network shares) — there the old `replace` behaviour is retained, i.e. the pre-fix behaviour, not
  a new failure mode. `except FileExistsError` re-checks parseability only because a *corrupt*
  sidecar should not be able to block a repair write forever; the guard is
  `_read_cache_meta(key) is None`, and that function already maps `(OSError, ValueError) → None`.
* *Why this shape is minimal.* In the uncontended case the probe branch runs only when no sidecar
  exists, so `os.link` always succeeds: **identical behaviour to LIVE, by construction**, for every
  prepare that is not racing. The change is inert except in the race.

**Cost:** two files, `+76/−7` in the installed file over 5 hunks (signature, docstring, write
tail, call site, comment) plus a 93-line test. `ruff check` clean on both candidate files and both
base copies; `ruff format --check` clean on the installed file.

| Risk | Assessment |
|---|---|
| The `os.link` fallback silently reverts to the old clobbering behaviour on a filesystem without hard links | Accepted and deliberate: the fallback preserves today's behaviour rather than introducing a new failure mode. The cache lives at `C:\ProgramData\…` on `C:`, which reports `FileSystemType : NTFS` (`Get-Volume`, read-only, `evidence/cache-sidecars-and-timing.txt`), so the atomic path is the one that runs and the fallback is defensive. A silent-degradation log line would be nice; it is not worth widening a minimal carry, and it is noted here instead |
| A corrupt sidecar could block a repair write forever | Guarded: `FileExistsError` is followed by `_read_cache_meta(key) is None`, and that function maps `(OSError, ValueError) → None`, so an unparsable incumbent is replaced |
| The probe's measurement is dropped on a collision | Intended. The dropped write is a *measurement for a key that was never promoted*; the retained write is the authoritative promotion marker. Dropping the measurement cannot cause a re-encode; dropping the marker does |
| The fix under-delivers vs the reported symptom | Stated in §6 rather than papered over. Eviction and the unexplained 07:53:54 event are independent producers |
| Installing LF over the installed CRLF file | Same as every prior carry on this line; `git hash-object` identity is the proof (byte counts differ only by CR count). Python is indifferent; no encoded byte is affected |
