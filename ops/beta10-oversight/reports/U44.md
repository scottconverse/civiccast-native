## II. Root cause

**OBSERVED in the producer's own source, and this is the whole mechanism:**

* every video sub-chain ends in `videorate`, and `videorate` is forced to push **one closing duplicate frame** at a sub-chain boundary — `gst_video_rate_duplicate_to_close_segment`, `gstvideorate.c:1054/1063/1077`, plus the `count < 1` branch at `1267-1290` that no property can switch off;
* at the boundary the leg's `concat` handles the **next** sub-chain's segment first and updates its base — `gstconcat.c:589` — **before** forwarding that duplicate. The duplicate is therefore clipped under the NEW segment and its running time lands **D seconds in the future**, D = the sub-chain's own duration: **10.033 s** at the 10 s sub-chain, **25.033 s** at the 25 s one that took government off air;
* `gst_base_ts_mux_find_best_pad` picks the next pad on the queued heads' timestamps, and `gst_aggregator_wait_and_check` then sleeps until the clock reaches the chosen head's running time. The muxed **video** stream starves for ~D; **audio plays on.**

**Why every existing counter reads healthy (OBSERVED):** U30's sink-pad flow ladder counts *arrivals*; the mux-src ladder and the aggregate S9-5 stall watch count mux **output as a whole**. One starved stream out of two looks healthy to all three, and video is still arriving — it is just not airing. In the base arms the `mux-in` interval line says so in as many words:

```
span=   6.0s src_d=  281 arr=  461 (v= 180 a= 281) deficit=  180  <- deficit ~= video
```

## III. The fix

`civiccast/egress/gst/engine.py` installs **one always-on BUFFER probe on the mux VIDEO sink pads** that DROPs an arrival only when **both** arms fire.

| symbol | line | value / role |
|---|---|---|
| `_MUX_ARRIVAL_CADENCE_BOUND_NS` | 597 | `2_500_000_000` — arm A: `running_time − previous_accepted_rt > 2.5 s` |
| `_MUX_ARRIVAL_AHEAD_BOUND_NS` | 598 | `1_000_000_000` — arm B: `running_time − pipeline_running_time_ns > 1.0 s` |
| `self._mux_pad_arrival_rt` | 871, re-created 2084 | per-pad reference of the last **accepted** arrival; advances only on accept |
| `self._mux_pad_arrival_drops` | 872, re-created 2085 | per-pad drop tally |
| `_pipeline_running_time_ns()` | 1287 | the pipeline's own running time, or `None` when unreadable |
| `_install_mux_pad_arrival_guard(pad, pad_name)` | 2197 | install site |
| `_make_mux_pad_arrival_guard(pad_name)` | 2216 | the probe factory; body 2273–2313 |

Installation is at **engine.py:2126**, inside the same `else:` arm of `_install_mux_input_counters` as U37's airing frontier — a pad whose BUFFER probe was refused is not registered, so it is neither counted, nor judged, nor guarded, and it is named by the `WARN` that already fired. `_pipeline_running_time_ns` returns **`None`** for an unreadable clock, deliberately distinct from a measured `0`, and `_pipeline_running_time_ms` is re-expressed on it (its own contract, `0` for both, unchanged). Those three lines are the whole of the change's removals.

The probe body, verbatim (engine.py:2273–2311):

```python
def _guard_mux_pad_arrival(pad: Gst.Pad, info: Gst.PadProbeInfo) -> Gst.PadProbeReturn:
    with contextlib.suppress(Exception):
        if self._mux_pad_stream_label(pad) != "video":
            return Gst.PadProbeReturn.OK
        _pts, running_time, _base = self._measure_first_buffer(pad, info)
        if running_time is None:
            return Gst.PadProbeReturn.OK
        pipeline_running_time = self._pipeline_running_time_ns()
        previous = self._mux_pad_arrival_rt.get(pad_name)
        if previous is None or pipeline_running_time is None:
            self._mux_pad_arrival_rt[pad_name] = running_time
            return Gst.PadProbeReturn.OK
        if (
            running_time - previous <= _MUX_ARRIVAL_CADENCE_BOUND_NS
            or running_time - pipeline_running_time <= _MUX_ARRIVAL_AHEAD_BOUND_NS
        ):
            self._mux_pad_arrival_rt[pad_name] = running_time
            return Gst.PadProbeReturn.OK
        drops = self._mux_pad_arrival_drops
        drops[pad_name] = drops.get(pad_name, 0) + 1
        print(f"CTRL mux diagnostic: dropped future-dated video arrival pad={pad_name} …", file=sys.stderr, flush=True)
        return Gst.PadProbeReturn.DROP
    return Gst.PadProbeReturn.OK
```

**Why the conjunction is safe rather than a heuristic (OBSERVED).** The legitimate drain-then-rebase switch step is **1.753 s** — large enough to clear arm A — but it sits *at* the switch's running time (measured ahead of the clock by **0.003 s**), so arm B is false and it airs. Only an arrival both far past the previous one **and** far ahead of the clock is dropped. The label is resolved lazily (`_mux_pad_stream_label`), so the guard is inert until caps are negotiated, and the body is wrapped in `contextlib.suppress(Exception)` because it runs on a streaming thread and must never be able to take a channel off air by raising.

## VIII. The coordinator note's question — `elements=52/61`
