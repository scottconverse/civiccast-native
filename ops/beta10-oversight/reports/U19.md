### U16 part 2 — engine-side diagnostics (`egress/gst/engine.py`)

**`cc0e270f`** (6 hunks) — *the diagnostics that decompose a one-sided rebase step*:

- **hunk 1** (`@@ -402`): module level — `_NEW_LEG_STREAM_LABELS = ("video", "audio")`,
  `_DIAGNOSTIC_NONE = "none"`, and `_seconds_or_none(value_ns)` (one shared formatter, so
  every diagnostic spells the same value the same way).
- **hunk 2** (`@@ -1694`): `GstPlayoutEngine._make_mux_first_buffer_reporter(pad_name)` (a
  closure returning the pad probe) and `_install_mux_input_diagnostics()`.
- **hunk 3** (`@@ -2109`): the call site — `self._install_mux_input_diagnostics()` armed once
  at pipeline build, because "the start of a worker's timeline is the other end of the same
  question the reload diagnostic asks".
- **hunk 4** (`@@ -2706`, +215, the largest hunk): `_rebase_reference_diagnostic`,
  `_measure_first_buffer`, `_new_leg_first_buffer_diagnostic`,
  `_make_new_leg_first_buffer_reporter`, `_arm_new_leg_rebase_diagnostics`,
  `_mux_pad_stream_label`, `_mux_first_buffer_diagnostic`.
- **hunk 5** (`@@ -3139`): the single-read discipline — the pipeline-time read happens
  **once**, in the branch that uses it, and both the applied value and the report come from
  that one read ("a second read a tick later would print a reference that is not the one the
  offset was actually set to").
- **hunk 6** (`@@ -3163`): the two guarded `contextlib.suppress(Exception)` print/arm blocks —
  the decomposed rebase-reference line, and arming the per-stream first-post-offset-buffer
  observation *between* the offset application and the hold release, "so no buffer can reach
  a probe without already carrying the rebase offset". Guarded because "a diagnostic must
  never be able to abort a commit".

**`6e7e95a0`** (2 hunks) — *read the new leg's first buffer where the rebase offset is
visible*: `_new_leg_selector_first_buffer_diagnostic`,
`_make_new_leg_selector_first_buffer_reporter`,
`_arm_new_leg_selector_diagnostics`, and the call site next to the previous arming. The
comment states the reason this second diagnostic exists at all: `Pad.set_offset` materialises
at the **crossing to the peer**, so the tail src pads of `cc0e270f` report the leg's own
pre-offset timeline while the selector-side pads report the post-offset one.
