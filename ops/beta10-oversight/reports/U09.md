## 6. Doubts and known gaps

1. **The backport is wider than the five named commits, unavoidably** (§3). The installed base predates the
   restart-recovery feature and the whole retention-provider feature, so `daemon.py` carries the feature
   plus 1d4eae14 (255 lines vs 1d4eae14's 122), `automation.py` carries the startup block and the dedup in
   addition to `c25c2f4f`'s 39 lines, and `store.py` carries 86 lines no named commit touches. Only
   `retention.py` and `tap_worker.py` are exactly their named commits' net changes. If the coordinator
   intended a strictly minimal change, the minimal set is not physically available — the named commits do
   not apply to this base without the feature they modify.
2. **The `run_forever` startup reconcile call (`automation.py:1126–1145`) is not asserted by any test.**
   OBSERVED: every test in `test_daemon_stale_state_recovery.py` calls `daemon.reconcile_stale_state()`
   directly (20 call sites), and nothing drives `run_forever` and asserts the startup sweep. I included the
   block because U06's headline fix (a pid-less claim left by a crash mid-start, on a non-`auto_start`
   channel) is only live in production if the sweep is actually wired at startup; dropping it would make the
   fix inert while every test still passed. `_reconcile_dead_encoders_this_pass`'s call site *is* covered
   (7 `run_once(...)` call sites in the recovery module). Also OBSERVED: the pass-watchdog test's
   `_IdleDaemon` exposes neither method, so the `getattr` guard makes the startup block a no-op there —
   which is why that 30-test module is unaffected. **This is a deliberate scope decision for the
   coordinator to confirm or reject (rejecting it means deleting that one block from the candidate).**
3. **The pristine side of the differential is the live package, not the staged copy.** `installed-base`
   holds only the five files, so a plain `sys.path` run resolves `civiccast` from Program Files (a regular
   package beats a namespace portion). The live files are sha256-identical to `installed-base` (§5), so the
   contrast is valid, but "pristine" in §4.4 means *the running station's package*, not the staging copy.
4. **`recover_stale_state` has no test coverage outside one module.** OBSERVED: `grep -rn
   recover_stale_state tests/ --include=*.py` matches only `test_daemon_stale_state_recovery.py`. The
   Postgres implementation is exercised there against a **fake session factory** (`PostgresEgressStore(
   _Factory())`, line 422), not a real PostgreSQL — the one-transaction/rollback path is asserted, but no
   real DB ran it.
5. **The 36 residual shared failures were not individually triaged.** The brief's bar (every overlay failure
   also fails on pristine) holds with an empty regression set, but I did not confirm that each of the 36 is
   environmental rather than an interaction with the installed base that this backport should have fixed.
6. **Not verified:** no station soak, no live-station run, no installer/package build — none was asked for,
   and the live station was not touched (no service action, no write under `C:\Program Files` or
   `C:\ProgramData`). Nothing was installed into the live package. No `git push`, tag, merge or commit; the
   worktree is untouched and `HEAD` is still `6b4391b1`. The repo's 5-lens self-audit is a pre-push gate and
