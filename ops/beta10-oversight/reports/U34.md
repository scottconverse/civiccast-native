## 2. The watchdog action — before and after

### 2.1 Before (`2b9b9f67`)

**OBSERVED** (`git show 2b9b9f67:civiccast/egress/gst/engine.py`). One judgement, on the mux SRC
aggregate, inside `_check_stall`:

* **Predicate:** `elapsed >= self.stall_timeout_s` where `elapsed` is time since *the aggregate
  counter* last moved (`engine.py:2667` pre-fix; the S9-5 watchdog). `stall_timeout_s <= 0` was an
  operator opt-out (`engine.py:2661`).
* **Action, first branch:** if a deferred replacement is READY and waiting, force the boundary —
  the channel changes leg without a restart.
* **Action, otherwise:** print to stderr
  `CTRL stall: no output for {int(self.stall_timeout_s)}s - quitting for daemon restart`
  (`engine.py:2751` pre-fix) and set `self._error = ("stall", "output stalled")`
  (`engine.py:2755`) → worker exits 1 → daemon relaunches.
* **The blind spot:** because the predicate is the *sum* over the mux, a channel whose video branch
  fed nothing but whose audio branch was healthy kept the aggregate climbing and was never judged.
  U30 §4.4 measured exactly this: 390 → 244 buffers/5 s (the audio-only rate) during the live
  reload-7 freeze. The message the operator finally got, if any, came from the daemon's escalation
  and said "output", never "video".

### 2.2 After (`5397c069`)

**OBSERVED** (`civiccast/egress/gst/engine.py`). The aggregate judgement is unchanged, byte for
byte. Added alongside it:

* **Where it runs:** `_check_stream_stalls(now)` is called **only** from `_check_stall`'s
  output-ADVANCING branch (`engine.py:2625` hunk → `return self._check_stream_stalls(now)`), i.e.
  precisely the branch where the aggregate is blind by construction. When the aggregate itself is
  flat the aggregate path owns the decision, as before.
* **What is judged:** `_required_stream_labels()` (`engine.py:2790`) → `{"video"}` always, plus
  `{"audio"}` iff `self.audio_selector is not None` (computed per check, not latched, so a graph
  rebuilt without an audio branch is not judged for having no audio). Caption/subtitle pads are
  excluded from judgement and stay in the logged flow ladder; a pad that has not produced since the
  reference was armed is left to the first-output budget (`_stream_ever_seen` is additive and never
  cleared, so a stream that fed the mux before a commit is still judged after it).
* **Reference baselining:** `_arm_stream_stall_reference(now)` (`engine.py:2808`) is called at arm
  time, next to `_snapshot_mux_input` (`engine.py:2516` hunk), and from `_reset_stall_reference` at
  commit settlement (`engine.py:2786`), so the two watchdogs always agree about when the current
  window started.
* **Commit window:** while `pending["commit_in_progress"]` is true the per-stream reference is
  pushed forward silently (`engine.py:2903-2905`) — the commit watchdog owns that window, and the
  healthy-run test asserts no `CTRL stall` line appears across a swap.
* **Action on a judged stream** — the existing action, kept: first
  `_force_ready_deferred_switch(reason=f"{label} stream stalled after replacement preroll; forcing switch")`
  (`engine.py:2916`); if that returns False, print to stderr and quit:

  ```
  CTRL stall: no {label} buffers for {int(elapsed)}s ({ctx_text}) - quitting for daemon restart
  ```
  (`engine.py:2931`), where `ctx_text` is `last reload id={id} stage={stage}` from
  `_reload_context` (`engine.py:2920-2923`), and set `self._error = ("stall", f"{label} stream stalled")`
  (`engine.py:2938`) → worker exits non-zero → daemon relaunch.

* **Shared rescue:** the forced-deferred-switch predicate was extracted to
  `_force_ready_deferred_switch(*, reason)` (`engine.py:2943`) and is now called by both paths
  (`engine.py:2680` aggregate, `engine.py:2916` per-stream) so the two cannot drift.
* **Reload context:** `_reload_context: tuple[int, str] | None` (`engine.py:775`) is recorded at
  `("prepared")` (`engine.py:3679`), `("committing")` (`engine.py:4343`), `("cleanup-failed")`
  (`engine.py:4680`) and `("committed")` (`engine.py:4711`); the live reload-7 case renders
  `last reload id=7 stage=committed`.

The wording deliberately does **not** reuse the aggregate's `no output for` — an operator (or a
test) must be able to tell which watchdog named the stall; and the tests assert the aggregate line
is *absent* when the per-stream one fires. The line is ASCII and on stderr because the daemon reads
the worker's stderr tail into the operator's `last_error` state row.

**OBSERVED, by reading the code path; INFERRED as to which fires first on the live box.**

## 13. Doubts

1. **The bound's real-world margin is inferred, not measured.** 63 ms worst observed gap vs a
   10 s default is comfortable, but I only measured on an idle machine with two pipelines. If the
   coordinator wants a product-load cadence number, that is a separate unit (and it needs the live
   station or a sandbox soak).
2. **`_check_stream_stalls` judges the longest-silent pad only**, one line, one exit. With both
   required streams silent the aggregate path has already handled it, so I believe this is
   unreachable in practice; it is a deliberate choice (one informative line) rather than a proved
   invariant.

   `commit_in_progress` true forever, the per-stream watchdog would go quiet. The aggregate path
   has the same property, and the commit watchdog owns that window, so U34 did not change the
   exposure — but it is worth knowing that U34's second watchdog inherits that dependency.
