**Lane:** Critical — persisted playout behaviour on a live station's egress path; a regression here is a station going dark.

**The rule as implemented (OBSERVED in the diff):** an ACTIVE channel is never dark while its program is being
prepared. A start/relaunch that begins with the channel already airing launches the worker **immediately on the
fallback slate**, and hands the prepared program in afterwards through the ordinary seamless reload. A hand-off
whose program cannot be prepared **keeps the slate** and leaves the retry to the existing slate-replan policy.

Labels: **OBSERVED** = read from a real command run in this unit (command quoted) or from a quoted log line;
**INFERRED** = a conclusion drawn from observed facts and named as such.

### 2.3 What changed

* **`egress/daemon.py`** — the rule. `_SLATE_FIRST_HANDOFF_REASON` and
  `_SLATE_FIRST_ACTIVE_STATES = frozenset({"ON_AIR", "FALLBACK_SLATE", "TRANSITIONING"})` (module constants);
  `_PreparationState.SLATE_FIRST`; the slate-first branch inside `_start_steps` (candidate L2072–2143) which, for an
  active channel with no prepared reload, resolves the fallback source, writes `FALLBACK_SLATE`, starts the slate
  worker and returns `_PreparationState.SLATE_FIRST` **without** blocking on the program's conform;
  `_hand_off_slate_first_program` (L4561) which hands the prepared program back in through the ordinary reload path;
  `_keep_slate_after_failed_hand_off` (L4592); and the read-only `has_pending_preparation` (L4537).
  The `slate_first` flag is threaded `_request_reload` → `_try_content_reload` → `_drive_preparation` →
  `_PendingPreparation.slate_first` → `_poll_preparation`.
* **`egress/automation.py`** — one gate so a neighbouring policy does not fight the rule: `_check_slate_replan`
  returns early while the daemon is preparing this channel's program (`_daemon_has_pending_preparation`, an optional
  capability read with `getattr`). Without it the slate-replan pass queues a *second* reload against the conform the
  hand-off is waiting on, which reaches `_cancel_preparation` and re-conforms the same program.

`_begin_relaunch` is the **only** call site that passes `slate_first=True`. The persistent-worker flag is untouched:
the slate launch is an ordinary `_start`, so it spawns through the same launcher with `CIVICAST_WORKER_PERSISTENT=1`
(**INFERRED** from the code path; the flag itself is set by the launcher, and the real-worker test asserts it — §3.5).

### 2.4 The scope boundary — and why it is not a free choice

The brief's rule and the committed crash-loop escalation ladder give **different first moves for the same event**:
one non-zero worker exit on an ON_AIR channel. The ladder (pre-existing, deliberately pinned) retries the
**program**, and reaches the slate only at `streak >= _LIVE_SOURCE_FAILURE_FALLBACK_STREAK`, measured at 405.0 s.

The candidate implements the rule **only where the darkness was measured and where the station runs** — the
asynchronous preparer. The load-bearing guard (candidate L2075–2081):

```python
            elif (
                slate_first
                and previous_state in _SLATE_FIRST_ACTIVE_STATES
                and prepared_reload is None
                and self._fallback_source_provider is not None
                and self._preparation_executor is not None
            ):
```

The last clause is what keeps the ladder intact on the synchronous path (where the daemon blocks anyway, so no
slate-first gain exists). Removing it is a 22-test regression, measured once and re-derived fresh in §3.3. The
choice between "rule wins everywhere" and "rule where the station runs" is a **product question** and is filed as
`..\questions\U47.md` **Q1** (three options; option 1 = as implemented). The candidate *is* option 1. **Q1 is
unanswered**, and `questions\U47.md` Q2 (the 5 s bar) and Q4 (cold start) are also open.
