### 2.3 Fix — reload-time tail floor (`21d9a715`)

`daemon.py:4009-4061` `_avoid_schedule_tail_plan`, called from `daemon.py:4190-4199` guarded
`if not force_fallback and boundary_at is None:`. Constants
`_SCHEDULE_TAIL_FLOOR_SECONDS = 30.0` (`daemon.py:317`) and
`_SCHEDULE_TAIL_BOUNDARY_MARGIN_S = 1.0` (`daemon.py:324`). It resolves the schedule at
`now + tail_seconds + margin` = the closing item's `plan_end_at + 1 s` — a boundary that is
**independent of the sampling instant**, which is why it deterministically lands past the closing
item and onto the next one. It returns the original plan (never `None`) for every failure mode,
because a declined plan sends the caller to `_request_reload`'s terminate-and-restart fallback.

**N = 30.0 s, justified:** landing a restart measured ~2.2 s of preparation + ~2 s to first
output + ~2.4 s of exit-and-respawn in the 02:58 trace; 30 s is ~3× that, half of automation's
own 60 s rollover lead, and far below the ~360 s slate fill horizon.

## 3. Item 3 / coordinator item 2 — the plan-build-time gap absorb (Option D)

### 3.1 What was implemented

`civiccast/egress/source_plan.py`: `SCHEDULE_GAP_ABSORB_SECONDS = 30.0`. When the instant a plan
is built for has **nothing at all to air**, and the next published item is due within the window,
the plan is built from that next item, started at that instant — early by at most the gap. The
rollover boundary then resolves to a program, so the channel never leaves its program and no
slate epoch exists to cut out of. Wired into both production providers:
`civiccast/egress/automation.py:2634-2645` and `civiccast/cli.py:1157-1164`.

### 3.2 The guards

- a plan with anything to air is never replaced — a join-in-progress resume of live content is
  content, not a stub;
- a gap **larger** than the window still returns `None` (filler is the honest answer);
- an instant **before** the published log begins is not absorbed;
- a negative window is a `ValueError`;
- the default stays `0.0`, so the library's documented D42 behavior is unchanged for direct
  callers.

### 3.3 `force_fallback` and the provider boundary, as measured

`automation.py:2634` (`cli.py:1157`): `max_segments=1 if gstreamer_engine_selected() else 8` — on
the live station a slot's plan is exactly **one** segment, which is the shape §2.1 describes.
(The previously quoted `automation.py:2633` was stale; corrected in the source comments by
`e6dbae24`.)

### 3.4 Item 4 — how the two constants interact

| | `SCHEDULE_GAP_ABSORB_SECONDS` (30.0, source_plan.py) | `_SCHEDULE_TAIL_FLOOR_SECONDS` (30.0, daemon.py:317) |
|---|---|---|
| Acts at | plan **BUILD** time, provider layer | plan **RELOAD** time, daemon layer |
| Fires when | the instant has nothing to air and the next item is due within 30 s | a reload is resolved at wall-clock `now` (`boundary_at is None`, not force-fallback) and a short closing-plan remainder was produced |
| Effect | start the next item early, in the plan — the channel never leaves its program | resolve the boundary 1 s past the closing item's recorded end, so the restart carries the **next** item |
| Cannot cover | a case where the caller resolves outside the published log | a case where the plan already has live media to air |

They are complementary and deliberately the same number: both encode "a slate epoch plus an
exit/restart costs more than starting the next item early by ≤30 s". `21d9a715` is kept in full.

### 12.5 Two defects in my own proof scripts, found and fixed

Both were mine, both were caught by a probe or by the proof's own identity, and both were fixed
before the final runs above.

1. **Proof 2's probes were testing the wrong objects.** `getattr(module, "SCHEDULE_GAP_ABSORB_SECONDS")`
   raised `AttributeError` for `automation` and `cli` — both import the constant *inside* the
   building function, so it is a local, not a module attribute — and `_plan_from` was probed as a
   provider method when it is a *nested* function inside `build_source_plan_from_schedule`. Fixed by
   adding `local_import_binding()` (a `co_varnames` check) and `nested_defs()` (an `ast` walk that
   prints `name@enclosing@lineno`), then re-running both sides. The corrected probes are the table in
   §12.3; without the fix the probe would have reported a false ABSENT on a change that is present.
2. **Proof 4's counter algebra was wrong in a way that hid the removals it was measuring.**
   `Counter.__sub__` clamps at zero, so `X = R − G` dropped every line whose count went down and the
   identity `residual == X − D` failed for `automation.py` on the first run (`PROOF 4 failures: 1`,
   `|D|=36 |residual|=22 |X|=0`). Fixed by adding `sub()` using `Counter.subtract()` plus a
   zero-filter, and using it everywhere. The corrected run gives `|D|=58 (+36/−22)`,
   `|residual|=58 (+22/−36)`, `X EMPTY` — i.e. the honest statement of the U05 drift, which the
   clamping version would have under-reported.
