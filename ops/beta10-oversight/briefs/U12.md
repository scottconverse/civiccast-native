## Goal
For a sink configured to carry video and audio, the relay never keeps emitting audio-only HLS: after any
(re)start it either produces video+audio or it is restarted again promptly (bounded, logged), until video is present.

## B. Implement (red then green), smallest change that meets the goal - coordinator's preferred design:
1. Explicit stream mapping that REQUIRES video for a video sink (e.g. `-map 0:v:0 -map 0:a:0` or equivalent),

   supervisor then restarts it (verify the restart cadence is bounded and not a tight loop - if it would be, add a
   short backoff). Keep audio-only sinks (if any exist) working unchanged.
2. Post-(re)start verification: after a relay (re)start, check the relay's newest output segment(s) for a video
   stream within a bounded window (reuse whatever probe tooling the module already has); if still audio-only,
   restart again (bounded attempts, then log an ERROR each further attempt at a low rate).
