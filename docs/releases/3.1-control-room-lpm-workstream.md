# 3.1 Control Room LPM Workstream

**Status:** Draft, local-only planning artifact  
**Date:** 2026-06-29  
**Related spec:** `docs/spec/3.1-control-room-lpm-studio-proof.md`  
**Related ADR:** `docs/adr/0019-control-room-device-control-tsr-sidecar.md`

## Summary

This workstream prepares CivicCast 3.1 for studio-control proof at Longmont
Public Media. It does not change the 3.0.1 beta release stream and must not be
pushed, merged, or tagged until the project director explicitly authorizes that
step.

The work starts from the existing 3.0 control-room foundation. The runtime
already has production-device records, device profiles, control surfaces,
timeline cues, sessions, cue-fired audit rows, device-command rows, a keyring
secret pattern, and a TSR sidecar. The 3.1 work hardens that foundation into a
real studio surface: versioned cues, Test Mode and On-Air Mode, operator locks,
safe-state/panic, OBS/vMix live evidence, state/tally, sidecar supervision,
support bundle evidence, and a station-device evidence matrix.

## Implementation Narrative

The first implementation pass is documentation and contracts. The 3.1 spec pins
the safety rules, proof language, and device scope before product code changes.
ADR 0019 stays Proposed until ratified, but it now names the station-device
evidence boundary and the operational consequences of owning a supervised TSR
sidecar.

The second pass extends the backend model. Existing control-room tables are
reused. Cue edits become versioned once a cue has been fired. Fired-event audit
rows store the cue version and redacted action snapshot. Sessions gain mode,
lock, reconnect, idle-expiry, and mode-transition audit behavior. Safe-state cues
are stored per surface or channel scope and are locked during On-Air sessions.

The third pass builds the safety layer. Test Mode is enforced server-side and is
not a visual-only banner. On-Air Mode requires confirmation, the right role, a
session lock, a configured safe state, healthy sidecar, network safety, and
material-state freshness. Panic/safe-state is a first-class recovery operation.

The fourth pass adds credentials and network safety. Secrets stay in the OS
keyring and device topology stores only secret references. Device adapters refuse
unsafe network destinations by default and log any setup-admin override.

The fifth pass makes the TSR sidecar an installed, supervised runtime dependency.
The sidecar must be started, health-checked, restarted on crash, version-checked,
and surfaced in the UI and support bundle. A missing sidecar means device control
is unavailable.

The sixth pass adds OBS and vMix proof. OBS is pinned to obs-websocket 5.x. vMix
uses the HTTP `/api` status/function surface and TCP/TALLY where appropriate.
vMix input rename is not a 3.1 cue action. Unsupported vMix functions return an
explicit not-exposed response. Fixture tests are captured from real OBS/vMix
sessions so local CI can run without live processes.

The seventh pass builds the UI around the dispatcher instead of around device
adapters. Device Inventory, Cue Builder, Dry Run, Live Fire, Safe State, Proof
Log, and Support Bundle all use the same backend contracts. Dry Run records a
material-state fingerprint, and Live Fire refuses only when state material to the
cue changed.

The final pass is evidence. Local evidence covers unit, fixture, live OBS, live
vMix, failure conditions, burst-fire, sidecar restart, support bundle, and local
GauntletGate. Station-device evidence records what happened on the real
equipment.

## Local Verification Command

Run the local-only runner from the repo root:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/run_local_3_1_control_room_ci.ps1
```

The runner writes artifacts under `artifacts/local-ci/`. It never pushes, merges,
tags, or opens a pull request. It is allowed to fail while this draft workstream
is still being implemented; failures are local development evidence, not release
evidence.

## Exit Criteria

This workstream is ready for station-device evidence capture only when the local
runner passes, the OpenAPI artifacts are regenerated and clean, the UI can
rehearse cues in Test Mode, OBS and vMix live integration pass locally, support
bundles redact secrets, and the evidence matrix has no unlabelled row. A mocked
row may remain, but it must be visible and excluded from station-device release
claims.
