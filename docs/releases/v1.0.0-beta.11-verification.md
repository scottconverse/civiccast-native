## Known limits

Native call timings exclude shared-lock wait and complete caption latency. Periodic output checks establish sampled decoding/freshness/continuity, not semantic transcription accuracy or coverage of every second. CPU-only Medium Whisper fallback has not demonstrated real-time capacity. NVIDIA CUDA support does not imply AMD/Intel GPU support.

A pre-fix three-channel exercise in a 10 GiB Windows Sandbox recorded overload catch-up/shed events and caption pauses, but the broken checker strongly confounds those observations; no pre-pause zero-cue evidence was captured. The helper out-of-memory/hang is explained by the PowerShell 5.1 serialization behavior above, but the evidence does not prove it caused every caption pause, and the pauses do not establish a product capacity failure or VM-resource causality. The corrected five-minute three-channel run passed the bounded checks described above. Its Sandbox had GPU disabled; Whistle was observed CPU-primary with no fallback, which does not prove every ASR path runs on CPU. No corrected Intel field rerun or Ryzen field test has been performed. The live host's three stations remained healthy during the isolated guest tests.

The caption implementation's earlier affected regression suite passed 293 tests; inherited automation/diagnostic failures were separately reproduced and documented. This is not a full-repository-green claim. Program-transition retries, lost acknowledgements and automatic capped relay-log trims have occurred during the longer observation. Whole-drive disk-space changes remain partly unattributed; game recordings/caches and Windows app updates were found, not a growing live caption archive. Short observer captures do not establish release-grade loudness. Physical broadcast hardware/headend acceptance and a real station field sign-off remain unproven.

No installation or restart was performed on the live station. Release package disposition remains subject to the publication decision; the staged D: kit has not been published.
