## Operational finding: candidate builds auto-dispatch a pruner (2026-09-18)

**Every `native-beta-candidate-artifacts` run auto-dispatches a
`gate-a-station-acceptance` run for its own sha, and Gate A's cleanup prunes
`C:\CivicCastTester\candidates\` and `C:\CivicCastTester\kit-staging\` down
to `{its sha + baseline sha}`. Therefore BOTH directories are transient even for
the CURRENT candidate. Nothing of value may be left there; expect them to be
emptied to `{newsha, baseline}` seconds after any build completes.**

This cost two artifacts on 2026-09-18: the signed `ef76be80` installer
(`bee7a689...`, 243,041,960 bytes) and the `8d5730a5` installer
(`60886a4d...`, 243,038,800 bytes) were both pruned out of `kit-staging\`.

Evidence of the mechanism (with an attribution limit stated honestly): the
`ef76be80` kit was written by its assemble job at 07:25:20 and was gone by
07:28:18; the only scheduled pruner in that window was the auto-dispatched Gate A
run `35319349498` (created 07:25:29 for head `8d5730a5`). That run later reached
`completed/failure` at 07:37:14. **The auto-dispatched pruner is the operative
mechanism; the exact run that removed `ef76be80` is not conclusively
attributed** -- an earlier claim that its cleanup had provably run before its job
list settled is WITHDRAWN as unsupported.

The prune's keep-set, verified from run logs: `prune_local_candidate_roots.ps1`
keeps `-CurrentSha` PLUS `baseline.source_sha`, logging
`Pruning local candidate roots, keeping: <sha>, <baseline sha>`.
