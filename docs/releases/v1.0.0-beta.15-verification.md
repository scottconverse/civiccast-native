## Package observations

One actual fresh installation ran in a 6 GiB Windows Sandbox with networking
and virtual GPU disabled. Setup exited 0 after 14 minutes 49 seconds, from
22:31:56 to 22:46:45 MDT on October 12, 2026. Service registration and station
activation completed, and the installed service reported healthy at the
current schema. This was one clean offline installation, not a cross-version
upgrade or repeated-install test.

The installed optional native setup wizard launched without a manually supplied
WebView runtime-folder override and displayed its “Checking This Computer”
screen with Whistle CPU-primary and Whisper-fallback wording. The installed
Help page rendered as noted in the package-boundary section above.

The password-file ACL probe passed under both a normal user and SYSTEM while
the test supplied a deliberately incorrect environment username. For the
normal user, grants were limited to that caller, SYSTEM, and Administrators;
for SYSTEM, grants were SYSTEM and Administrators. Inheritance was removed.
This verifies those tested identities, not every unattended deployment mode.

The actual signed installer refused a downgrade with exit 129 in 7.139 seconds
when the installed-version and Add/Remove Programs metadata were temporarily
marked Beta 16. The installer made no observed installation changes: service
PID/state, executable hashes, activation selector, registry identity,
installation-progress hash, health and the saved next-programme pointer were
unchanged. Test metadata was restored afterward. This simulates a newer
installed version through metadata; it is not a test against a real Beta 16
package.

The packaged 20-second Welcome sample played in a 20-second schedule slot
created with the existing schedule API, then returned the feed to fallback
slate. The test identified the sample and slate from decoded HLS video, not
filenames or the initial source label. The UI schedule form has a one-minute
minimum; the 20-second slot used the schedule API specifically to verify the
short bundled asset.

## Known rollover limitation

In a separate observation, a 60-second schedule slot containing the 20-second
Welcome clip repeated programme rollovers. The slate continued flowing, while
the daemon remained in `TRANSITIONING` during the retained observation and
worker logs showed rollover attempts. The observation does not prove an
indefinite stall. A separate 20-second slot completed normally. Repeated
rollover and the transition-status mismatch remain unresolved in Beta 15.
Confirm the actual HLS output and preserve logs before treating a changing
source status as proof that output stopped.

## Limits

Beta 15 has no demonstrated automatic restoration of old application files,
activation state and service state after a later installer failure has already
replaced payload files. The flat installation layout's late D3 refusal disables
filesystem rollback. If that late refusal occurs, repair with the complete kit
matching the newer installed version; do not uninstall or delete station data.
The early downgrade refusal above does not prove late-failure rollback.

No normal cross-version upgrade, interrupted-install repair, Beta 15 extended
soak, physical target-machine evaluation, broad audit, full CI pass, or
production cutover is claimed. A successful build or signature alone does not
establish those results.
