# v1.2 First-Run Gates Evidence

Run: `2026-05-18-v1.2-internal-hardening`

## Fail-Closed Contract

`civiccast.installer.service.run_first_health_check()` no longer reports
external provider lanes as `ok` when required credentials are missing or merely
present as placeholder/configuration strings. Provider lanes remain blocked
until a live verification command records real target evidence.

## Blocked Lanes Without Credentials

- `portal`: `credential_or_secret_required`; set `CIVICCAST_PORTAL_TOKEN`.
- `internet-archive`: `credential_or_secret_required`; set
  `CIVICCAST_INTERNET_ARCHIVE_ACCESS_KEY`.
- `youtube`: `credential_or_secret_required`; set
  `CIVICCAST_YOUTUBE_CLIENT_SECRET`.
- `local-nas`: `failed`; configure `CIVICCAST_NAS_ARCHIVE_PATH`.
- `subscriber-notifications`: `credential_or_secret_required`; provide
  `CIVICCAST_SUBSCRIBER_WEBHOOK_SECRET`.

Podcast feed generation and signed-transcript verification remain local checks
and are not described as real external provider proof.

## Configured But Unverified Inputs

Placeholder or configured credentials for portal, Internet Archive, YouTube,
and subscriber notifications still return `credential_or_secret_required`
until a live verification pass records redacted evidence. A configured local
NAS path returns `ok` only after a real write/read/delete hash probe succeeds;
a missing or unreachable path returns `failed` with an operator action naming
`CIVICCAST_NAS_ARCHIVE_PATH`.

## Offline Bundle Evidence

`verify_airgapped_install()` reports each verified model filename with the
SHA-256 computed from its file bytes. Missing artifacts report the missing
filename and direct the operator to copy the offline bundle into the VM before
rerunning verification.
