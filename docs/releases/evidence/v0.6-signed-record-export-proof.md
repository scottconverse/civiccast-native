# v0.6 Signed Record Export Proof

Run: `2026-05-14-v0.6-summary-signed-records`

## Contract Proven

The v0.6 signed-record path exports only server-side approved summaries. The
staff record route loads the persisted summary state, rejects missing or
unapproved summaries, calls `SignedRecordExporter.export(...)`, stores the
artifact bytes through the record store, and returns timestamp/provenance
metadata.

## Deterministic PDF/A-3B Contract Proof

The local deterministic proof checks the actual bytes that are timestamped. It
does not substitute a prefix-only assertion and does not claim a third-party
veraPDF run. The proof requires these markers in the rendered PDF bytes:
This is historical deterministic contract fixture proof, not a valid PDF/A-3B
document in v1.0.0.

- `%PDF-1.7`
- `PDF/A-3B`
- `sourced-claims.json`
- `provenance.json`
- `approval.json`
- `timestamp-token.der`
- `%%EOF`

`validate_pdfa3_contract(...)` returns:

```text
PASS PDF header present
PASS PDF/A-3B conformance marker present
PASS sourced claims, provenance, approval, and timestamp attachment names present
PASS EOF marker present
```

## Timestamp Proof

`DeterministicTimestampAuthority` binds the rendered artifact bytes to an
RFC 3161-shaped deterministic fixture proof with:

- `algorithm = sha256`
- `artifact_digest = sha256:<rendered-pdf-digest>`
- deterministic token bytes in `token_der_b64`
- deterministic timestamp metadata for local fixtures

`verify_timestamp_proof(...)` rejects tampered payload bytes.
