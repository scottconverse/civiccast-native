# v1.2 native Windows clean-install attempt

Status: `blocked`

This follow-up attempted the requested native clean Windows proof through
Hyper-V and Windows Sandbox on the RTX validation host. It did not boot a native
Windows VM or Sandbox instance.

## Host Result

- Host OS: Windows 11 Home, version `10.0.26200`, 64-bit.
- Elevated query: passed. The probe ran as Administrator.
- `Get-VM`: blocked; the Hyper-V PowerShell command is not installed.
- `WindowsSandbox.exe`: blocked; the executable is not installed.
- `vmms` service: blocked; the Hyper-V Virtual Machine Management service is
  not present.
- Feature inventory: only `VirtualMachinePlatform` and
  `Microsoft-Windows-Subsystem-Linux` are enabled; `HypervisorPlatform` is
  disabled; `Microsoft-Hyper-V-All` and `Containers-DisposableClientVM` are not
  listed.
- DISM feature query: both `Microsoft-Hyper-V-All` and
  `Containers-DisposableClientVM` return `feature name unknown`.

## Enable Attempt

Elevated PowerShell then tried controlled `-NoRestart` enable commands:

```powershell
Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V-All -All -NoRestart
Enable-WindowsOptionalFeature -Online -FeatureName Containers-DisposableClientVM -All -NoRestart
```

Both returned `feature name unknown`. No reboot was requested and no global
feature change was made.

## Upstream Requirement Check

Microsoft documents that the Hyper-V role cannot be installed on Windows 10 Home
or Windows 11 Home:

<https://learn.microsoft.com/en-us/windows-server/virtualization/hyper-v/get-started/Install-Hyper-V?branch=live>

Microsoft also documents that Windows Sandbox is supported on Pro, Enterprise,
Pro Education/SE, and Education editions, and is not currently supported on
Windows Home:

<https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/>

## Conclusion

Native Hyper-V/Sandbox clean-install proof is host-blocked on this Windows 11
Home machine. The v1.2 Windows beta path remains the Windows installer plus WSL2
Ubuntu flow from ADR 0003; that path passed through the disposable WSL2
fresh-user offline wheelhouse install in
`docs/releases/evidence/v1.2-clean-windows-install-proof.md`.
