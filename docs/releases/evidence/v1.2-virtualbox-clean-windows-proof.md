# v1.2 VirtualBox clean Windows installer proof

Status: `partial`

This evidence records the native clean Windows VM path exercised on the RTX
host after Hyper-V and Windows Sandbox were proven unavailable on Windows Home.

## Clean VM

- VM engine: Oracle VirtualBox `7.2.8r173730`, installed through elevated
  `winget`.
- Guest OS: Microsoft Windows 11 Enterprise Evaluation, version `10.0.26200`,
  64-bit.
- ISO SHA-256:
  `A61ADEAB895EF5A4DB436E0A7011C92A2FF17BB0357F58B13BBC4062E535E7B9`.
- Install mode: unattended Windows install into a fresh VirtualBox VM named
  `civiccast-cleanwin-vbox`.

## Initial Finding

The pre-fix Windows setup artifact installed successfully in the clean VM:

- Setup SHA-256:
  `0941200686BE09657728693CBDD691082BEF1566804DE7F8723E756D547EB0EF`.
- Silent installer exit code: `0`.
- Installed app:
  `C:\Users\civiccast\AppData\Local\CivicCast Installer\civiccast-installer.exe`.
- Registry entry: `CivicCast Installer`, version `1.1.1`.

The launched installer UI blocked at `WSL2 Ubuntu missing` and told the
operator to run `wsl --install -d Ubuntu` manually. That was not acceptable for
the beta handoff goal.

## Fix Validated In VM

The installer was updated so the WSL-missing lane has an enabled
`Install WSL2 Ubuntu` action. The packaged Tauri app now launches:

```powershell
wsl.exe --install -d Ubuntu
```

through a Windows elevation prompt instead of only displaying the command.

The rebuilt setup artifact installed successfully in the same clean VM and
proved the new action path:

- Rebuilt setup action-proof SHA-256:
  `00BC095C9AA1B75726B5DFF7842E43A2C6DB2BB64062D984B5D86171A1312539`.
- Silent installer exit code: `0`.
- Installed app path still present:
  `C:\Users\civiccast\AppData\Local\CivicCast Installer\civiccast-installer.exe`.
- Launched UI displayed `Install WSL2 Ubuntu`.
- Clicking the action opened a Microsoft-verified UAC prompt for Windows
  Subsystem for Linux, and after approval Windows downloaded and installed WSL
  `2.7.3`.

The VM proof also exposed an important edge case: after the Windows WSL
installer ran, `wsl.exe --status` returned success even though no Ubuntu
distribution was installed. The final Tauri command therefore checks
`wsl.exe -l -v` for Ubuntu before treating the lane as ready, and `Retry` no
longer launches elevation. Only the `Install WSL2 Ubuntu` action starts the
Windows WSL installer.

Final release-artifact gate rebuild SHA-256 after that hardening:
`2D77B47A0BA4EB753506F6CA72458BFB046499825B8C6C7FA3566DB7E47071CF`.

## Remaining VM Boundary

The VM could not complete WSL2 runtime validation because nested virtualization
is unavailable in this VirtualBox guest. Guest `wsl.exe --status` returned exit
code `0` and reported `Default Version: 2`, but also reported:

- WSL2 cannot start because virtualization is not enabled on this machine.
- No Linux distributions are installed.
- Component Based Servicing has a reboot-pending key.

That is a VM validation boundary, not a return to the prior product gap. The
host WSL2 fresh-user lane remains the passed runtime proof for installing
CivicCast from the offline wheelhouse.
