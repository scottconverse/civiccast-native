## Implemented Contract

- Default-off federation posture.
- Station actor discovery through WebFinger and `/ap/actor`.
- Required station base URL and private-key path for enabled mode.
- Signed ActivityPub inbox for `Follow` and `Undo Follow` activities.
- Remote actor key lookup and HTTP Signature / Digest verification.
- Instance blocklist, limited allowlist, and approval-only moderation behavior.
- Optional authorized fetch for actor, outbox, and follower reads.
- Inbox rate limiting.
- Durable follower, outbox, and delivery-attempt persistence.
- Signed outbound `Accept`, `Reject`, and publish `Create` delivery.
- Staff moderation endpoints for status, follower listing, approval, reject,
  block, outbox evidence, and delivery evidence.
- Operator console Federation screen with disabled/enabled states, policy
  summary, follower moderation tabs, and delivery evidence.
- Installer ActivityPub setup panel covering station identity, keygen, policy
  mode, restart, and console handoff.
- Lab-only local interop allowance for controlled loopback/container proof.

## Public Rollout Boundary

The implementation path is complete for enabled federation. CI uses local
signed actors and delivery receivers instead of a committed public fediverse
account. The local GoToSocial proof validates signed actor-document interop
inside a controlled lab environment; it is not a public fediverse compatibility
claim and does not exercise a live public `Follow`/`Accept` roundtrip. A
station that wants public rollout should run the signed federation smoke test
and a redacted target-instance proof against its chosen partner instance.
