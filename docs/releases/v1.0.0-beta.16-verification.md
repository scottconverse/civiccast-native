### Upgrade environment limitation

The actual candidate stopped with `Recovery snapshot needs 31398357326 bytes
plus 256 MB reserve; setup stopped before replacement.` The guest had
27,410,255,872 bytes free on an 85,764,059,136-byte system volume; DiskPart
reported an 80 GB disk with zero unallocated space. No snapshot-space guard was
bypassed. After refusal, the original Beta 15 service was Running, `/health`
was healthy with current schema, and the original administrator could sign in
and retrieve the saved three-channel station profile. This establishes safe
refusal on this disk, not a completed Beta 16 upgrade. Successful upgrade
verification requires a test volume with sufficient free space.

### Upgrade in the replacement VM

The owner authorized a larger test environment. Hyper-V was enabled and the
host restarted with explicit authorization. A Windows 11 Enterprise Evaluation
guest was installed on a 160 GiB virtual disk. The Beta 15 baseline's initial
6 GiB / two-CPU install timed out in its 300-second `gemma4:12b` self-test;
guest pagefile peak usage was 5,410 MiB. The same installer passed in
13 minutes 27 seconds with 10 GiB RAM and four virtual CPUs, reporting healthy
Beta 15 and database revision `0089_contribution_media_control_requests`.
This supports resource pressure as a contributor, not a proven root cause.

The actual signed Beta 16 upgrade ran from 20:22:29 to 20:42:54 UTC on
October 14. Station activation and database migration passed, but Windows
service registration failed. The log shows the upgrade health check starting
the service before registration; the identity configuration requires a stopped
service. The exact guard exception was not retained in the installer log,
so its wording is a source-based diagnosis. Setup exited 118, restored Beta 15,
and preserved the original administrator login and exact saved station profile.
No runtime smoke or uninstall was performed after that failed upgrade.
Receipts are in `C:\Dev\CivicCast-TestVM\evidence` on the owner machine.

The correction must stop and confirm the service is stopped before identity
configuration, preserve the guard, and retain the installer's final start.
It changes shipped code and requires a corrected signed candidate and actual
package verification. The earlier candidate's fresh-install result does not
establish the corrected candidate's result.
