## Candidate change summary

The candidate adds automatic Whistle recovery. Failed probes use a 30-second
initial cooldown followed by capped delays of 60, 120, 240 and 300 seconds;
retries continue while the affected channel has audio. A slow warning is
reported after 10 seconds, and the 30-second watchdog terminates an
unresponsive child. The 210-second queue bound is `(3 × 2 + 1) × 30` seconds
of serialized request allowance, not a delivery guarantee. The default queue
holds at most 42 five-second WAV chunks; catch-up after sustained overload is
finite. Diagnostic records are bounded and live audio is not archived.

This description does not establish an original stall root cause. The Beta 12
public-install checker retained only the first Python traceback line, and its
post-upgrade recorder failed while converting a value for JSON serialization;
the persisted failure details did not establish the underlying cause. Those
historical observations remain scoped to Beta 12.
