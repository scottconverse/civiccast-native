## The experiment

A temporary Windows service (`CivicCastSession0Spike`: NSSM wrapper, **LocalSystem,
auto-start**, bounded `SWAPS=60 INTERVAL=10` ≈ 10-minute run per boot) wrapped the
production worker. The owner rebooted the machine and deliberately waited ~6 minutes
at the pre-login lock screen before entering a PIN. The service's own run log, the
output file timestamps, and the (admin-read) Security log are independent channels.

## What each channel proves

- **Run log identity line** — `whoami` and `SessionId` captured *inside* the service
  process: `nt authority\system`, session 0.
- **Security 4624** — no interactive logon between boot and 06:23:26 (boot-time
  virtual accounts UMFD-*/DWM-* excluded; they register LogonType 2 with no human).
- **NTFS timestamps + probes** — output growth timestamped inside the no-user window;
  growth cannot be backdated by the payload writing its own log.
- **Prior same-day validation run** (05:47, SCM `Start-Service`, user logged in)
  showed identical behavior — the boot run is not a one-off.

## Out of scope here (tracked, out of this spike's scope)

Windows 11 SCM does not emit per-service 7036 "entered running state" events at boot
(only driver-load entries were present), so SCM-log corroboration is absent — the
three channels above stand in. Also not covered: long-duration stability (soak),
packaging/minimal closure, clean-machine install, live-peer/hardware sinks, service
recovery policy (NSSM was configured exit-no-restart for boundedness). The
production service wrapper is specified in the supervisor execution spec, not this
spike; the temporary service is removed after this evidence lands.
