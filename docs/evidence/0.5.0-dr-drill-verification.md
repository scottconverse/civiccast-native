# 0.5.0 — Disaster-recovery drills: verification

## Plain-language summary

Roadmap 0.5.0 promised "tested backup/restore drills, not just backup files
that have never been restored." This lands the drill: CivicCast now backs up
the real station database (not a proof token), restores it into a brand-new
database, and checks that every row came back exactly as it was — and it
crashes the channel-output process on purpose to prove CivicCast brings it
back automatically. Run it yourself with `civiccast dr run-drill --out
<dir>`, or trigger it from the operator console via
`POST /api/staff/installer/dr/run-drill`.

## Technical summary

New module: `civiccast/dr/` (see its package docstring for the full honesty
statement on scope/boundaries).

- `civiccast/dr/backup.py` — SQLite backup via the sqlite3 backup API (never
  a raw copy of a live file), Postgres backup via `pg_dump`, a bounded
  head/tail-sampled media manifest, and a generic `snapshot_tables()` (row
  count + PK-ordered content checksum) that runs identically over SQLAlchemy
  against both the live source and the restored copy.
- `civiccast/dr/restore_drill.py` — the 0.5.0 gate: restores into a
  completely fresh SQLite file, verifies the alembic head
  (`civiccast.schema_check`), compares every table's row count + checksum
  against the backup manifest, and opens the restored database through the
  app's real stores (`PostgresAssetStore.list()`, `PostgresEgressStore.
  list_configs()`) to prove the app can actually read it.
- `civiccast/dr/crash_drill.py` — starts a REAL OS child process under the
  real `EgressDaemon` (production crash-detection/relaunch code path), kills
  it for real, and proves the daemon relaunches it.
- `civiccast/dr/report.py` — orchestrates all three and renders a two-voice
  markdown + JSON report.
- CLI: `civiccast dr run-drill --out <dir> [--database-url ...] [--media-root
  ...]`; exits non-zero on failure.
- API: `POST /api/staff/installer/dr/run-drill` (setup_admin/support_admin),
  wired through `civiccast.installer.service.run_dr_drill`. The existing
  proof-token `run_restore_rehearsal`/`build_restore_status` surface now also
  reports the last REAL drill result via the new `RestoreStatus.
  real_drill_summary` field.

### A production correctness finding surfaced while building this

`Base.metadata` binds every ORM table to `schema="civiccast"` (ADR 0008).
For SQLite, production resolves that prefix via `engine.execution_options(
schema_translate_map={"civiccast": None})` in `civiccast.app.
_create_database_engine` — **not** the `ATTACH DATABASE ':memory:' AS
civiccast` connect-hook `civiccast.db.base` registers for the fast in-memory
test path. Building a SQLite engine the naive way (`create_engine(f"sqlite:/
//{path}")`, matching `civiccast.db.session.get_engine`'s bare
`create_engine(url)`) queries the wrong, empty, per-connection in-memory
attachment and silently reads zero rows against a real on-disk file. The
drill's `civiccast.dr.backup.build_sqlite_engine()` mirrors the real
production engine construction exactly so this doesn't happen to the drill
itself; its docstring documents why. This was a test-harness trap for
*this drill*, not a bug in the shipped app (the app already builds its
engine the correct way) — flagged here for visibility, not fixed as
out-of-scope surgery.

## Honest boundaries (do not overclaim beyond these)

- **Media backup is a manifest + bounded sampled hash, not full-file
  replication.** Operators still need their own file-level media backup.
- **Postgres backup capture is implemented and executed in CI**, not in
  this local sandbox (no Docker here). It follows the same
  `pg_dump`/testcontainers pattern as `tests/schedule/test_real_postgres.py`
  (`tests/dr/test_postgres_backup.py`, gated identically —
  `CIVICCAST_RUN_POSTGRES_TESTS=1`). It correctly SKIPPED locally rather than
  fabricating a pass; the `ci-test.yml` `test` job's Docker-backed runner
  exercises it for real, machine-checked at every PR head by the claims
  verifier. **This SHA's bound test exercises capture (`pg_dump`) only** —
  the corresponding recovery path is not exercised here; it lives on the
  unmerged WS2 branch and will register as its own claim once that
  branch's history enters this branch's ancestry.
  <!-- claim:ws2-postgres-backup-capture -->
  See `docs/claims/claims.yaml`.
- **Crash-recovery drill covers daemon auto-restart only.** "A recording
  finalization interrupted mid-settle recovers on next scan" (the roadmap's
  second crash-recovery scenario) is NOT built in this pass — see the
  `civiccast.dr` package docstring for what that would take.
- **Multi-machine hot failover is NOT 0.5.0.** A second-box cold-standby
  restore looks exactly like this drill's restore step, run there against a
  copied backup set.
- **Real-hardware power-loss drills are beta**, out of scope here.

## Evidence: a real drill run against a seeded, alembic-migrated station
<!-- claim:ws2-sqlite-restore-falsification -->

Real alembic `upgrade head` against a fresh SQLite file (92 tables), seeded
via the app's own stores (3 assets, 1 schedule item, 1 egress config, 2
media files), then a full backup → restore → crash drill, then falsification
(deliberately dropping a row and confirming the drill fails):

```
== step 2: run the REAL full drill (backup + restore + crash) ==
overall ok = True
restore ok = True, tables checked = 92
  table=assets rows=3/3 matched=True
  table=egress_configs rows=1/1 matched=True
  table=egress_sinks rows=1/1 matched=True
  table=schedule_items rows=1/1 matched=True
  ... (88 more zero-row tables, all matched=True)
app_store_reads = {'assets': 3, 'egress_configs': 1}
crash drill ok = True
  crash[daemon_crash_restart] ok=True detail=pid 27256 killed; daemon relaunched pid 19516; state after relaunch = 'ON_AIR'
media manifest entries = 2

== step 3: FALSIFICATION — corrupt the restored db, expect the drill to FAIL ==
tampered restore ok = False (expected False)
mismatched tables = ['assets']
FALSIFICATION CONFIRMED: dropping a row makes the drill fail, as it must.
```

`civiccast dr run-drill` exits 0 on the pass above and 1 whenever
`report.ok` is `False` (confirmed directly, not inferred).
