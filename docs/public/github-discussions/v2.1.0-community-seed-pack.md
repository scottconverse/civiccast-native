## Announcements

### Title

CivicCast v2.1.0 — the public beta you can install by double-click

### Body

CivicCast v2.1.0 is the public beta for open-source civic meeting broadcast,
replay review, record export, and resident-facing publication. It installs on a
clean Windows 11 machine by double-click — we proved that end to end on a fresh
VM: installer → WSL2 helper → service start → first-admin and recovery kit.

What's new in v2.1.0 (the beta sprint):

- **Recording finalization with operator repair** — ended live sessions are
  packaged automatically, and terminal failures get a one-click Retry instead of
  database surgery.
- **Real trim** — saving a trim on a recorded asset re-renders the published
  video automatically.
- **CDN publishing** — packaged recordings can upload through a selected CDN
  (Bunny / Cloudflare R2); the public URL is only set after a verified upload.
- **Real provider adapters** — Internet Archive, YouTube, and SMTP email now
  ship as real adapters behind `CIVICCAST_PROVIDER_*=real` plus credentials.
  Deterministic mocks remain the default, so a fresh install stays simulated.
- **Live caption tap** — a station can fork live broadcast audio into the
  caption review queue (off by default; needs a local transcription model).
- **Recording provenance** and **honest retention copy** — the record is
  stamped at go-on-air, and expired assets are flagged for records review,
  never silently purged.

Best first test:

1. Download the v2.1.0 installer from the Release page.
2. Run a private rehearsal.
3. Publish a short replay.
4. Tell us where setup, the operator flow, captions, summaries, or records

## Development

### Title

Technical testers: review the v2.1.0 finalization, CDN, provider, and caption-tap surfaces

### Body

v2.1.0 promoted several subsystems from "implemented" to "production-wired" (see
`CAPABILITIES.md`). The useful technical questions for this beta:

- **Recording finalization → CDN**: does the worker package HLS, upload through
  the configured CDN (segments first, manifest last), and set `manifest_url`
  only after a verified upload? Does a CDN failure stay retryable without
  deleting the local package?
- **Real providers**: the Internet Archive, YouTube, and SMTP adapters are
  contract-tested against mock transports / a loopback SMTP server, never live
  services. Review the registry seam (`CIVICCAST_PROVIDER_*`) and the fail-fast
  credential handling.
- **Caption tap**: the egress audio fork → durable review queue path. Review the
  settle/quarantine logic and the hybrid worker lifecycle.
- **Operator repair**: finalization Retry and ActivityPub dead-letter Replay.

Please review:

- `docs/ops/cdn-and-providers.md`
- `docs/ops/background-workers.md`
- `docs/ops/finalization-worker-runbook.md`
- `docs/releases/v2.1.0-scope-and-evidence.md`
- The tests under `tests/live/`, `tests/platform/`, and `tests/captions/`.

The honest claim is:

> CivicCast v2.1.0 installs by double-click on a clean Windows 11 machine and
> runs the full meeting-to-publish workflow including CDN publishing and
> config-gated real providers. Live external-provider delivery and downstream
> broadcast compliance are not yet field-proven.

## Show And Tell

### Title

External provider and field-proof partners wanted (v2.1.0)

### Body

v2.1.0 ships **real adapters** for Internet Archive, YouTube, and SMTP email,
but they are contract-tested only — no live external calls have been made. We
need partners who can run them against real accounts and report back safely.

Lanes that need real-world proof before CivicCast claims them publicly:

- Internet Archive (real item upload via the S3-like API)
- YouTube (real broadcast/VOD via the Data API + OAuth)
- SMTP email and webhook subscribers (real relay)
- CDN publishing against a real Bunny or Cloudflare R2 zone
- ActivityPub federation with real remote instances
- Local NAS archive targets
- Live camera, NDI, SDI, or DeckLink handoff
- Cable/headend delivery beyond the software-headend proof

If you can test one of these with a real account, real hardware, or a real
station workflow, reply with the lane you can cover and what evidence you can
safely share. Do not include credentials or tokens in your reply.
