Title: Which optional provider or field-proof lane should CivicCast prioritize next?

Body:

Several CivicCast surfaces are implemented or scaffolded, but need real
station-specific proof before they can be described as field-proven:

- Internet Archive.
- YouTube.
- Email and webhook subscribers.
- Podcast feed discovery.
- ActivityPub federation.
- Local NAS archive targets.
- Cable headend delivery beyond local egress proof.
- NDI and physical video-output workflows.
- Streaming-TV app-store publication.

Good proof includes a non-sensitive test item, a redacted transcript or
runbook, the public or non-secret status result, confirmation no secrets or
resident data appeared in logs, the exact CivicCast version or commit SHA, and
the operator-facing step that triggered the provider setup.

Do not post API keys, OAuth secrets, passwords, recovery codes, private account
details, resident data, private meeting content, or unredacted logs. If proof
requires sensitive coordination, open a private/security contact first.
