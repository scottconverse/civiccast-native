## Announcements

### Title

CivicCast v2.0.9 is ready for real-user testing

### Body

CivicCast v2.0.9 is the current software parity release candidate for
open-source, self-hostable civic meeting broadcast workflows.

Good early testers include school boards, city boards and commissions, HOA
boards, nonprofit boards, public-access stations, community media teams, and
small public-interest broadcasters that want to run a controlled first
rehearsal before a real public meeting.

Start here:

- Release tag: `https://github.com/scottconverse/civiccast/releases/tag/v2.0.9`
- User manual: `docs/USER-MANUAL.md`
- Windows install guide: `INSTALL-WINDOWS.md`
- Tester packet: `docs/tester/START-HERE.md`
- Release scope: `docs/releases/v2.0.9-scope-and-evidence.md`

The v2.0.9 proof boundary is intentionally narrow. It proves
CivicCast-controlled local behavior: the inherited Windows new-user path from
v2.0.8 plus FileSink and loopback SRT channel-egress proof on one real Windows
tester machine. It does not claim downstream cable-headend acceptance, QAM
modulation, SDI/DeckLink output, EAS behavior, CEA-708 compliance, app-store
publication, legal certification, managed-service operation, or production
analytics proof without separate evidence.

Tell us what kind of organization you represent, which computer and operating
system you used, where setup first felt confusing, and whether you could run a
private first-broadcast rehearsal without coaching.

Do not post passwords, recovery codes, provider secrets, private keys,
subscriber data, private meeting content, or unredacted logs.

## Q&A

### Title

New users: where does your first CivicCast rehearsal get stuck?

### Body

This thread is for people trying CivicCast without deep server or Linux
knowledge.

The expected first rehearsal path is:

1. Download the release asset.
2. Verify the download.
3. Run the setup path.
4. Create the first admin.
5. Save the recovery kit.
6. Open System Health.
7. Verify backup and run restore rehearsal.
8. Connect a camera or upload a short test file.
9. Run a private first-broadcast rehearsal.
10. Confirm resident playback from a second browser.

Please tell us:

- Which step first made you hesitate.
- Whether the Windows helper explanation made sense.
- Whether the setup handoff to the operator console was clear.
- Whether the recovery kit felt understandable and important.
- Whether **ready**, **check before meeting**, and **do not broadcast yet**
  were clear enough before a meeting.
- Which guide answered your question, and which one did not.

Do not share secrets, recovery codes, private meeting content, subscriber data,
or private logs.

Which optional provider or field-proof lane should CivicCast prioritize next?

### Body

Several CivicCast surfaces are implemented or scaffolded, but need real
station-specific proof before they can be described as field-proven:

- Internet Archive.
- YouTube.
- Email and webhook subscribers.
- Podcast feed discovery.
- ActivityPub federation.
- Local NAS archive targets.
- Cable headend delivery beyond local egress proof.
- NDI and physical video-output workflows.
- Streaming-TV app-store publication.

Please describe the lane your organization cares about, what account,
credential, policy, hardware, or external system is required, and what
redacted evidence would make the result trustworthy.

Do not post credentials or private data. If proof requires sensitive
coordination, open a private/security contact first.

## Field Proof

### Title

Field proof wanted: cable headend, physical output, and provider validation

### Body

v2.0.9 proves local CivicCast-owned egress behavior with FileSink and loopback
SRT. It does not prove that a downstream cable headend, QAM modulator,
SDI/DeckLink device, EAS workflow, or app-store channel accepted the output.

This thread is for organizations that can help design controlled field proof.

Please describe:

- The target system.
- The required format or handoff.
- The people or vendors involved.
- The redacted evidence you can safely share.
- Any compliance, caption, loudness, emergency alert, or policy requirement
  that CivicCast must not over-claim.

Do not post credentials, private station information, private meeting content,
or unredacted logs.
