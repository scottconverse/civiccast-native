## Announcements

### Title

CivicCast v2.0.10 is ready for real-user testing

### Body

CivicCast v2.0.10 is the current public beta for open-source civic meeting
broadcast, replay review, record export, and resident-facing publication.

This release adds the next channel-egress validation step: CivicCast egress
continuity is now validated against an adversarial software headend under
network impairment. That means the local egress path has been tested against a
hostile receiver/analyzer that can reject known-bad streams, not only against a
happy-path loopback.

Best first test:

1. Install the latest release.
2. Run a private rehearsal.
3. Publish a short replay.
4. Report where the setup, operator flow, captions, summaries, or records
   review felt clear or confusing.

Please do not paste recovery codes, setup nonces, API keys, private meeting
content, private keys, passwords, or subscriber data into public reports.

Useful links:

- Release: `https://github.com/scottconverse/civiccast/releases/tag/v2.0.10`
- User manual: `docs/USER-MANUAL.md`
- Scope and evidence: `docs/releases/v2.0.10-scope-and-evidence.md`

## Development

### Title

Technical testers: review the v2.0.10 egress architecture and proof boundary

### Body

v2.0.10 adds the E.2 adversarial software-headend gate. The useful technical
question is no longer whether the local proof runner can emit a happy-path
stream; it is whether the supervisor and analyzer behave honestly when sources
swap, slate enters and exits, the encoder child relaunches, captions decode
back, and network impairment is present.

Please review:

- `docs/ops/channel-egress-runbook.md`
- `docs/releases/v2.0.10-verification.md`
- `docs/releases/v2.0.10-scope-and-evidence.md`
- The E.2 virtual-headend tests under `tests/egress/`

The honest claim is:

> CivicCast v2.0.10 validates egress continuity against an adversarial software
> headend under network impairment.

It does not yet claim real cable-headend acceptance, QAM, SDI/DeckLink, EAS, or
CEA-708 broadcast-chain compliance. Those need separate field proof.

## Show And Tell

### Title

External provider and field-proof partners wanted

### Body

CivicCast has implemented and scaffolded several provider and field lanes that
need real-world proof before the project should claim them publicly:

- Internet Archive
- YouTube
- Email and webhook subscribers
- Cloudflare R2
- ActivityPub federation
- Local NAS archive targets
- Live camera, NDI, SDI, or DeckLink handoff
- Cable/headend delivery beyond the software-headend proof

If you can test one of these with a real account, real hardware, or a real
station workflow, please reply with the lane you can cover and what evidence
you can safely share.
