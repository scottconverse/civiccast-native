# CivicCast 3.2 LPM Livestreaming Contract Lab

**Status:** Draft for local 3.2 work only
**Date:** 2026-06-30
**Scope:** Local development only. The current package includes Stage 0-1
profile contracts, Stage 4-5 fixtures/simulators/software probes, Stage 6-7
deterministic rehearsal artifacts, and Stage 8 local release-hardening plus a
reusable Virtual Media Studio bundle. A separate wall-clock soak runner can
repeat the Stage 8 lab for a requested elapsed duration and write endurance
evidence. It is not clean Windows install proof and does not claim station-device
evidence. Do not merge, tag, push, publish a PR, or alter the live beta stream
without a separate release decision.

## Purpose

CivicCast 3.2 turns the 3.1 control-room foundation into a proof-driven LPM
livestreaming lab. The goal is not to replace the active
`v3.0.0-beta1-lpm-fieldtest-r1` LPM beta candidate or disturb its tester
download path. The goal is to prove as much of the LPM software/hardware
contract as possible before CivicCast touches LPM's real production gear.

The lab has one product surface and three topology profiles:

1. **Fixed Studio + Livestreaming Studio** - the primary station path. TV Studio
   cameras and audio route into the Livestreaming Studio, where vMix on the
   streaming PC sees SDI/DeckLink and NDI/PTZ sources.
2. **Portable Field Kit** - the mobile livestreaming path. Panasonic cameras feed
   an ATEM Mini Extreme, the ATEM output reaches a vMix laptop through a Cam
   Link-type USB capture device, and the stream goes to Castr and LPM's YouTube
   stream over a portable network.
3. **Digitization OBS** - the OBS recording workflow used in LPM's digitization
   room. This is the natural LPM-used OBS proof target, but it is not by itself a
   live production-switching proof.

These are profiles of the same LPM Lab, not three separate products.

## Proof Labels

Every device-control claim must carry a proof label:

- **mocked** - useful for rehearsal only; not release evidence.
- **simulated-proven** - passed the stateful simulator or network-fault harness.
- **software-lab-proven** - passed against real local software such as OBS, vMix,
  or NDI tools.
- **api-contract-proven** - implemented against the vendor/API contract and
  exercised by strict fixtures or simulators, but not yet attached to LPM gear.
- **station-device-proven** - touched the real LPM device/path and produced saved
  evidence.

Mocked and simulated features are documented. They must never be described as
station-ready until they become station-device-proven.

## Topology Contract Source

The executable source of truth is
`civiccast/control_room/lpm_lab.py`. It defines the three profiles, their device
contracts, failure modes, proof labels, required absences, and egress
destinations. Tests in `tests/control_room/test_lpm_lab_profiles.py` lock the
profile facts that are most likely to drift.

Each topology source is a structured source record with a title, URL, access
date, source type, and claim IDs. Source types are `direct-lpm-doc`,
`vendor-doc`, `civiccast-inference`, and `station-device-confirmed`.
Inferences, such as the DeckLink Duo 2 channels 2/3/4 reading, are preserved as
inferences rather than promoted to direct LPM claims.

The profile source intentionally stores no credentials. The public LPM wiki
documents AIDA web-login defaults, but CivicCast treats those only as a setup
warning: runtime credentials must be operator-provided through the credential
store and must not appear in profiles, fixtures, logs, support bundles, or docs.

## Fixed Studio + Livestreaming Studio

This profile covers vMix on the streaming PC, DeckLink/SDI camera channels, NDI
sources, AIDA PTZ/VISCA, and the documented SQ5 audio path.

The DeckLink wording is intentionally precise. LPM's docs say routed cameras show
up in vMix as DeckLink Duo 2, 3, and 4, and the Soundpost setup says to add
DeckLink Duo cameras 2, 3, and 4. Blackmagic sells DeckLink Duo 2 as a
four-channel card. The best read is one DeckLink Duo 2 using channels 2/3/4, but
that is an inference, not a direct LPM hardware inventory statement.

The fixed-studio check catalog must include missing driver, missing card, missing
channel, mode mismatch, signal-unlocked, source-removed, API-disabled,
credential failure, NDI disappearance/reappearance, VISCA timeout, VISCA
command-not-executable, and TSR sidecar restart.

## Portable Field Kit

This profile exists because the portable kit has different failure modes from the
fixed studio. It must pass when DeckLink and PTZ are absent. It must model the
ATEM Mini Extreme, generic Cam Link-type USB capture, Behringer U-Phoria USB
audio, vMix laptop constraints, optional WiFi/hotspot, Castr, and LPM's YouTube
stream destination.

The portable check catalog must cover generic USB/UVC capture identity,
no-DeckLink/no-PTZ as expected states, ATEM unavailable, capture device identity drift,
USB reset, laptop resource ceiling, audio delay/sync warning, WiFi latency, WiFi
dropout, Castr unreachable, and YouTube destination confirmation.

The capture device is not claimed to be Elgato unless LPM confirms it. The lab
uses "Cam Link-type USB capture" as the claim.

## Digitization OBS

This profile covers OBS Studio in the LPM digitization room, plus Elgato Video
Capture and tape/deck source workflows. It is useful because it proves the OBS
integration against an LPM-used workflow.

The digitization check catalog must cover obs-websocket disabled, wrong password,
protocol mismatch, source missing, recording state, source removed, OBS restart,
capture device absent, and local recording evidence.

Digitization OBS is not a live switching proof and must not be used alone to
claim LPM production-control readiness.

## Eight-Stage Implementation Program

Stage 0 freezes the proof contract. It produces this spec, the executable LPM
Lab profile source, profile tests, proof-label rules, and the local-only boundary.

Stage 1 builds the deterministic contract-lab harness. It emits structured
profile-contract and check-catalog evidence for every required check declared by
the three topology profiles, captures those artifacts, and provides a single
local runner. Stage 1 does not execute real API fixtures, real stateful
simulators, real local OBS/vMix/NDI software, a clean Windows install, or LPM
station hardware. Later stages may upgrade individual rows to `simulated-proven`,
`software-lab-proven`, `api-contract-proven`, or `station-device-proven` only
after that proof actually runs.

Stage 2 hardens the backend control plane. It implements device inventory,
credential references, network-safety checks, state service, cue versioning,
dry-run, live-fire, sidecar supervision, proof log, support bundle, and OpenAPI.

Stage 3 builds the operator UI. It covers Device Inventory, credential setup,
Control Surface Setup, Cue Builder, Dry Run, Live Fire, Safe State/Panic, Proof
Log, Support Bundle, proof labels, stale-state explanations, and test/on-air
mode clarity.

Stage 4 proves real local software where it is installed and reachable. It is
designed to run against OBS, vMix, and software NDI senders/receivers, but the
artifact may only claim `software-lab-proven` for the specific local endpoint
whose probe completed successfully.

Stage 5 proves hardware API contracts. It uses Blackmagic/ATEM, DeckLink, VISCA,
NDI, USB capture, and network simulators/SDK fixtures to prove behavior before
station hardware.

The executable Stage 4-5 layer is opt-in from the local runner:
`scripts/run_lpm_contract_lab.py --execution-stage stage45`. In that mode,
CivicCast keeps the Stage 0-1 mocked catalog rows and appends separate
`api-fixture`, `stateful-simulator`, and optional `software-lab` events. This
prevents a mocked catalog row from being silently promoted to proof. The runner
supports `--probe-real-software` to record local OBS/vMix probe results. If the
endpoint is absent, the event remains `not-applicable`, uses `mocked` proof
level, and says that no software-lab proof is claimed.

`--require-software-lab` is profile/device-class aware. It fails unless every
selected profile software class has a passed local software probe. For example,
`digitization-obs` requires OBS only, while `all` requires both OBS and vMix.
This prevents an OBS-only proof from greenlighting vMix-dependent profiles.

The local CI runner treats OBS as the first Stage 4 software proof target. It
uses an already-reachable local OBS websocket endpoint when present. If it must
prepare OBS itself, it snapshots the user OBS websocket config, writes a
temporary no-secret local lab config, starts OBS, runs the software proof, and
restores the original config in a `finally` path. The OBS probe must complete a
real obs-websocket 5.x upgrade, Hello, Identify, and GetVersion request; plain
TCP reachability is not enough.

vMix software-lab proof remains separate: the official vMix 60-day trial
installer must be installed and its local `/api` endpoint must answer before any
vMix row may be called `software-lab-proven`. Until then, vMix rows are only
API-contract or simulator proof.

Stage 5 fixtures currently cover the API/protocol shapes CivicCast can validate
without touching LPM hardware: vMix `/api` status XML required fields and drift
rejection, obs-websocket 5.x Hello/request/response/event correlation, VISCA UDP
ACK/completion/error handling on port 52381, ATEM program/preview state fixtures,
generic UVC capture identity, DeckLink absence/mode/signal simulations, NDI
source disappearance/reappearance, and portable-network/Castr/YouTube dependency
failure simulations. These are local software/API proofs, not station-device
evidence.

The full Stage 6 target is end-to-end soak and chaos: three-channel activity,
source dropouts/recovery, sidecar restarts, app restarts, network faults,
support bundle generation, GauntletGate, elapsed soak evidence, and cleanroom
install proof. The current local `stage67` runner validates the plan and
readiness envelope only; elapsed wall-clock soak and cleanroom install proof are
separate evidence paths.

Stage 7 captures station-device evidence. It replaces software/api proof labels
with station-device-proven labels only where the real LPM equipment is touched.

The executable Stage 6-7 layer is opt-in from the same local runner:
`scripts/run_lpm_contract_lab.py --execution-stage stage67`. Stage 6-7 is
cumulative: it keeps the Stage 0-1 catalog rows, runs the Stage 4-5 local
fixtures/probes, and appends deterministic soak/chaos and station-readiness rows.
The Stage 6 rows validate a 12-hour, three-profile activity plan, channel
dropout/recovery points, sidecar/app/network failure expectations, and a
redacted support-bundle manifest without sleeping for 12 wall-clock hours.
Those rows may be `simulated-proven`; they are not a completed elapsed soak.

Elapsed soak evidence is generated by the separate wall-clock runner:
`scripts/run_lpm_contract_lab_wall_clock_soak.py`. For a four-hour local run:
`uv run python scripts/run_lpm_contract_lab_wall_clock_soak.py --duration-seconds 14400 --interval-seconds 300 --profile all --probe-real-software --require-software-lab --artifact-root artifacts/wall-clock-soak/<run-id>`.
That runner repeats the Stage 8 contract lab until the requested elapsed duration
is reached, writes `summary.json`, per-cycle artifacts, source-state hashes, and
a README, and fails if any required cycle fails or if elapsed time is short.

Stage 7 local rows are `station-readiness` rows only. They define and validate the
station evidence envelope LPM must fill in, including operator, timestamp,
profile, device evidence, media evidence, support-bundle path/hash, and station
contact. A locally generated template is intentionally `not-applicable` and
`mocked` until real LPM evidence is supplied. No local run may emit
`station-device-proven` just because the template exists.

Stage 8 release-hardens the local result. It prepares the release-hardening
manifest, known-limits note, local operator handoff, proof matrix, and reusable
Virtual Media Studio bundle. It does not run or require an elapsed wall-clock
soak inside the fast CI path. Elapsed soak evidence is attached separately from
the wall-clock soak runner when requested.

The Virtual Media Studio bundle is generated under the Stage 8 artifact root and
can also be written directly with
`tools/virtual-media-studio/civiccast-vstudio.py bundle write`. The bundle is
structured around profile packs, device plugin manifests, scenarios, probes, and
an extension contract so new hardware/software targets can be added without
rewriting the runner. It remains local lab software inside this repo for 3.2,
but its contracts are intentionally separable for a future standalone project.

## Gate Discipline

Work proceeds two stages at a time. Each slice runs GauntletGate Lite and fixes
to zero before the next slice. At the end of a stage, GauntletGate All runs in
canonical order - Lite, Walkthrough, Full - and issues are fixed to zero before a
local commit. Full/all is the heavy five-role audit lane and remains local-only
unless explicitly authorized otherwise.

Clean-machine testing uses the available Windows VM or a reset replacement. If a
stage does not yet have an installable artifact, the report must say that
cleanroom install proof is not applicable to that slice rather than pretending it
ran.

## Local-Only Boundary

This 3.2 work must not push, merge, tag, open a PR, publish a release, or change
the active `v3.0.0-beta1-lpm-fieldtest-r1` LPM beta tester download path. All
artifacts stay local until the release owner explicitly authorizes publication.
