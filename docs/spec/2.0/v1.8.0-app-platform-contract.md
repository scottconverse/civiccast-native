## Purpose

This document is the handoff between CivicCast backend contracts and the public
app shells. It defines what every app target consumes before platform-specific
build and store work begins.

The public naming guardrail applies here: public repo-facing docs should use
industry-standard or feature-specific language, not named incumbent vendors,
unless Scott explicitly approves that for a specific document.

## Required Shell Behavior

Every public app target must load `StationAppConfig` from
`/api/public/app/config` or a test fixture with the same shape.

Every shell must render, at minimum:

- Station identity.
- Platform label.
- Default channel identity.
- Live-state URL or live-state projection.
- Schedule-feed URL or schedule placeholder.
- VOD-catalog URL or VOD placeholder.

No shell may define a private replacement schema for station config, channels,
live state, schedules, or VOD catalog. Platform-specific adapters can transform
the shared contract into native UI state, but the inbound contract remains the
same.

## Boundary

v1.8.0 proves the shared architecture and walking skeleton. It does not claim
production native packaging, app-store publication, platform certification,
device remote-control polish, DRM, or platform-specific media-player behavior.
Those claims belong to later parity stages.

## Verification

Shell verification lives in:

- `civiccast/apps/app-platform-shells/test/shell-contract.test.mjs`

The test suite verifies:

- The expected target directories exist.
- Every target manifest points at `/api/public/app/config`.
- Every target imports the shared shell runtime.
- The sample station config covers every public app target.
- The shared shell runtime renders the required station, channel, live,
  schedule, and VOD fields from one config object.
