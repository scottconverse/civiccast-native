# v1.8.2 App Store Readiness And Certified Integrator Guidance

This document keeps v1.8.2 honest: the CivicCast product owns the shared app
runtime, app contract, target artifacts, monitoring expectations, and reference
proof. External developer accounts, store review, and device certification are
deployment requirements.

## Shared Contract Rule

Every app target must use the same station config contract from
`/api/public/app/config`. Target-specific shells may adapt input model, package
format, and store metadata, but they must not fork channel identity, live
playback URLs, VOD catalog rules, captions, audio tracks, chapters, or schedule
feeds.

## Certified Integrator Handoff

Certified integrators should:

- Build from `npm.cmd run build` in `civiccast/apps/app-platform-shells`.
- Use the generated `dist/build-report.json` as the artifact manifest.
- Configure the station's approved app config URL.
- Verify live playback, VOD playback, captions, audio tracks, chapters,
  schedule browsing, station branding, and channel branding before submission.
- Record external account, store review, and device certification steps in the
  deployment file for that station.

## Monitoring Checklist

Each target should report or expose enough diagnostics to confirm:

- station config fetch
- live state fetch
- live playback URL present
- VOD catalog fetch
- schedule feed fetch
- caption track present when advertised
- app branding applied

The canonical machine-readable checklist lives in
`civiccast/apps/app-platform-shells/store-readiness.json`.

## Platform Difference Policy

Platform differences are acceptable only when they are explicit and tested. The
current v1.8.2 categories are browser local proof, living-room local proof,
living-room package proof, mobile local proof, and mobile package proof. Later
device work can add stricter proof classes without changing the shared content
contract.
