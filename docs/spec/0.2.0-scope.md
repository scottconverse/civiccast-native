# CivicCast 0.2.0 — Scope: Live Delivery at Scale

**Status: accepted (decisions locked 2026-07-07).** This is the committed scope for the 0.2.0
release line. Supersedes the review draft in `Desktop\CODE\civiccast-0.2.0-scope-v0.2.md`.

## The goal, plain English

Public meetings are **live**, and a controversial one can spike to **thousands** watching at
once (LPM has seen 3,000; a district-wide school-board vote could hit 10,000). Today every one
of those viewers pulls the live stream **directly from the one station PC** — which saturates
its uplink at a few dozen viewers and knocks everyone else offline. 0.2.0 lets the station
produce **one** stream and put a **CDN in front of it under load** so the CDN fans it out to
the whole town, and **proves it with a real load test at meaningful scale.**

## What's already built vs. what's missing

**Built:**
- CDN adapter protocol + provider selector (`CIVICCAST_CDN_PROVIDER` = off/bunny/cloudflare_r2/stub; ADR 0006). **Provider is already a config choice.**
- The finalization worker already uploads **finished recordings (VOD)** to the CDN (segments-first-manifest-last, points `manifest_url` at the CDN, retryable failure classification, never deletes the local copy).
- Trusted-proxy handling for when a CDN fronts the portal.

**Missing (this release):**
- **Live is still served direct from the station** (loopback `manifest_url`) — the 10k bottleneck. Nothing fans out live.
- **A concurrent live-viewer load test** — greenfield.
- **Reproducible CDN provisioning** — the app can *use* a CDN, but standing one up is manual.

## Architecture (the honest design) — local-default, adaptive switch to CDN

**The local station server is the default and serves the stream directly.** For a normal
meeting (dozens of viewers) nothing touches a CDN — no external dependency, pure
station-in-a-box. **The CDN is a surge valve, brought in only when load demands it**, then
viewers are switched to it.

The mechanism that makes an in-flight switch safe:
- **A configurable live delay buffer (X seconds).** The player runs a few segments behind live. When a surge is detected, that buffer is the window during which the player keeps playing already-buffered content while the backend brings up the CDN and redirects the source — so the viewer doesn't stall. Trades a few seconds of liveness for switch-safety (fine for meetings; nobody interacts through the stream).
- **Early trigger, not at saturation.** The station flips at ~50–60% of its measured serving ceiling (concurrent-viewer / bandwidth threshold), so the switch happens with headroom — not *through* an already-choked uplink. Getting this threshold right is the one critical part.
- **Switch = hand viewers the CDN manifest URL.** New joiners get it immediately; existing viewers are signaled to swap source (small hiccup, covered by the buffer).

Two ways to "bring up the CDN" on surge (config choice):
- **Cold (lean default):** don't touch the CDN until the threshold; then start pushing segments and redirect. Zero cost at idle; the delay buffer covers the cold-start.
- **Warm standby (option):** quietly push segments to the CDN in the background all along, so a surge is just a URL flip — seamless, at a small constant upload cost.

Getting the live stream to the CDN works whether or not the origin is public (do NOT assume NAT):
- **Push** (works behind NAT, no open ports): the `hls` sink uploads segments+manifest to the CDN — a continuous version of the built VOD finalization upload. Reuses the R2/Bunny adapters. Reference path.
- **Pull-origin** (if the origin is reachable, or via a **Cloudflare Tunnel** for a NAT'd station): the CDN caches the station's live HLS short-TTL. Lower per-segment overhead.

→ **Reference = local-default + cold-switch, push-to-R2 on surge** (no open ports, zero
egress, reuses built code). Warm-standby and pull-origin/Tunnel documented as options for
lower switch-latency.

## Deliverables

1. **Local-default live serving with an adaptive switch to CDN under load.** Default: the station serves the live stream directly (no CDN). When a CDN is configured *and* the station crosses its load threshold, it brings up CDN live-publishing (cold or warm) and switches viewers to the CDN URL, with the delay buffer covering the transition. Pieces: a **load monitor + configurable threshold**; the **CDN live-publish path** (extends the built VOD upload to rolling segments); the **source-switch signal** to players; and the **configurable live delay buffer**. Clean fallback to local when the CDN is off/unreachable.
2. **Concurrent live-viewer load-test harness that validates the SWITCH.** Simulates N clients pulling the rolling live manifest+segments on the real cadence, and specifically **ramps viewers past the switch threshold** to confirm the whole adaptive path: the station detects the surge, switches to CDN, and viewers ride through on the buffer **without stalling** — *then* the CDN holds the thousands. Measures success rate, stall rate, join latency, and switch-transition smoothness. Runnable locally + as a manual/CI job.
3. **Published results, honest.** In `docs/releases/`:
   - **Direct-from-station:** find the ceiling (expected: tens of viewers).
   - **CDN-fronted:** prove it holds a few **thousand** concurrent live viewers, and argue it scales toward 10k (the station produces one stream regardless of audience — the CDN is the variable).
4. **OpenTofu provisioning module** for the reference CDN (R2 + the segment-serving config), so a station can stand up its CDN reproducibly — with the module structured to add Bunny/Fastly/Akamai as peers.
5. **A scale claim in the docs backed by (3)** — replacing 0.1.0's honest "not yet load-tested at large scale."

## Definition of done
Published, reproducible load-test evidence that a CDN-fronted **live** broadcast serves
thousands of concurrent viewers with the station producing one stream — and the docs claim
exactly that, no more. Off-by-default; the stock single-PC install still works unchanged.

## Decisions (locked 2026-07-07)
- **Live delay buffer: target ~15s, 30s hard ceiling.** Sizes the switch window; keep it at/under 15s in normal operation.
- **Cold switch is the default** — **zero CDN cost at idle** (a station on donations pays nothing until the night the whole town shows up). Warm-standby is an opt-in for stations that want a zero-hiccup switch. This also biases the reference config toward **zero-standing-cost** options (R2's zero egress).
- **Provisioning = OpenTofu** (MPL-2.0, open-source; setup layer). **Runtime provider abstraction = the existing `CDNAdapter` protocol** (not OpenTofu — it's setup-time IaC, it can't do request-time routing/switching).
- **(Deferred to build, not blocking):** push-to-CDN vs. pull-origin/Cloudflare-Tunnel transport — decide per provider + whether the origin is publicly reachable (do NOT assume NAT).
