# CivicCast v1.7.3 to v1.8.9 Upgrade Path

Audience: station admins, technical operators, and integrators moving an existing v1.7.3 installation to the v1.8.9 parity release candidate.

Status: v1.8.9 release-candidate upgrade runbook. Do not use this document to claim live hardware validation, app-store publication, legal certification, or managed-service operation without separate evidence.

## Boundary

This runbook covers CivicCast-controlled software upgrade work:

- preserving station configuration and media;
- proving backup, restore, and rollback readiness;
- applying the package update and database migrations;
- proving the v1.8 parity feature set after the update.

It does not prove external app-store acceptance, live router hardware behavior, live caption appliance behavior, hosted relay connectivity, production analytics traffic, or legal compliance.

## Preconditions

- The station is currently on v1.7.3.
- No public meeting, live event, or scheduled publish job is in progress.
- The admin has the v1.7.3 rollback artifact and SHA-256 recorded.
- The admin has the reviewed v1.8.9 release-candidate artifact and SHA-256 recorded.
- The backup destination has enough free space for database, configuration, media manifests, caption state, records state, publish state, and station profile metadata.
- External credentials are available to the operator but are not copied into evidence documents.

## Phase 1 - Preflight

1. Confirm the installed version is v1.7.3 from the app UI, `civiccast --version`, or `GET /api/version`.
2. Configure and verify backup storage with `POST /api/staff/installer/backup`.
3. Run restore rehearsal with `POST /api/staff/installer/restore/rehearsal`.
4. Record the v1.7.3 rollback installer path and SHA-256 with `POST /api/staff/installer/update-rollback/rollback-artifact`.
5. Run rollback rehearsal with `POST /api/staff/installer/update-rollback/rollback-rehearsal`.
6. Generate a redacted support bundle with `POST /api/staff/installer/support-bundle`.
7. Run update preflight with `POST /api/staff/installer/update-rollback/preflight`.
8. Open the maintenance window with `POST /api/staff/installer/update-rollback/maintenance-window`.

Stop if any step returns `needs_attention`, `not_set_up`, or `not_configured`.

## Phase 2 - Apply Update

1. Close operator-facing browser windows and confirm no live session is active.
2. Verify the v1.8.9 release-candidate artifact SHA-256 before running it.
3. Run the installer/update package.
4. Let the installer-managed storage flow apply database migrations. For technical-admin source installs, run `uv run alembic upgrade head`.
5. Start CivicCast and verify `GET /health` reports healthy.
6. Verify `GET /api/version` reports the expected v1.8.9 release-candidate identity.

## Phase 3 - Post-Upgrade Proof

Run `POST /api/staff/installer/update-rollback/post-update-proof`, then prove these parity surfaces before returning to public operation:

| Surface | Minimum proof |
| --- | --- |
| Native OTT and mobile app suite | App platform config loads and target build artifacts are current. |
| Gated and private video access | Public catalog enforces a gated item and an open item correctly. |
| VOD preroll messaging | Preroll policy metadata is visible in the playback policy surface. |
| Full multi-zone CG bulletin board | Operator can preview a multi-zone board and fetch the HLS/render plan. |
| AV router control | Operator can preview manual and scheduled router take commands without sending hardware commands. |
| Caption appliance integration | External caption payload enters the normal caption review queue. |
| Squeezebacks and L-bar live overlays | Operator can preview the overlay compositor plan and z-order. |
| RTMP cloud ingest relay | Operator can generate the remote ingest plan; live hosted proof requires relay credentials. |
| Expanded audience measurement and reporting | Operator analytics report loads and EPG/GA4 exports are available where configured. |
| Contributor submission portal | Public contributor submission, status lookup, and operator review queue work. |

If a surface depends on external accounts, hardware, or traffic, record it as `complete_with_external_dependency` in the parity evidence matrix rather than pretending the local upgrade proved it.

## Phase 4 - Rollback

Rollback is required if the service cannot start, migrations fail, `/health` fails after restart, `/api/version` does not match the expected release-candidate identity, or a core station workflow cannot be recovered.

1. Stop CivicCast.
2. Reinstall the recorded v1.7.3 rollback artifact.
3. Restore station data from the verified backup destination.
4. Verify `GET /health`, `GET /api/version`, backup status, restore status, and safe-to-broadcast.
5. Keep the failed v1.8.9 support bundle and post-update proof output with the release-candidate evidence.

## Evidence To Record

- v1.7.3 starting version.
- v1.8.9 artifact filename and SHA-256.
- Backup verification timestamp.
- Restore rehearsal timestamp.
- Rollback artifact path and SHA-256.
- Rollback rehearsal timestamp.
- Update preflight timestamp.
- Maintenance window timestamp.
- Post-update proof timestamp.
- `/health` and `/api/version` output.
- Parity evidence matrix status for all ten gaps.
