## 4. Fix a pre-existing time-of-day-fragile ActivityPub retry test clock leak

Discovered while gating: 4 tests in `tests/activitypub/test_retry_worker.py`
and `test_retry_replay.py` fail deterministically on clean `main` (reproduced
with my changes stashed) once real wall-clock UTC passes `_NOW` (2026-06-10
12:00). Root cause: `deliver_publish_activity` enqueues failed deliveries via
`enqueue_failed_delivery` **without** passing a `now`, so `next_attempt_at` is
computed from real `datetime.now(UTC)` while the tests scan with a fixed-past
`_NOW` — the retry looks "not yet due" and never becomes due/dead-letters.
Latent on main (shipped in v2.1.0); harmless in production (real-now enqueue +
real-now scan are consistent) but makes the suite pass only within a ~1h
wall-clock window.

Fix (house style, no production behavior change): add an optional `now:
datetime | None = None` to `deliver_publish_activity` and thread it to
`enqueue_failed_delivery` (default `None` → real now). Update the test helper
`_enqueue_failure` to enqueue at `_NOW` so the suite is deterministic.
